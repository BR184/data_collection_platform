# 质量看板模块二次对齐差异记录

> 记录日期：2026-06-18  
> 新平台：`D:\projects\data_collection_platform`  
> 老平台：`D:\projects\spidergitdata-dev`
>
> 本文只做二轮复核和差异标记，不直接改代码。对齐标准仍然是：老平台已有入口、字段、指标、跳转、导出和筛选在新平台等价可达；同一数据范围下展示值应一致。

## 老平台基线

### 入口

老平台 `webapp/src/views/PageHome/Home.vue` 中“质量看板”模块包含两个入口：

1. `研发质量看板`：跳转 `/ninePersonalQuality`，页面 `webapp/src/views/PageNinePersonalQuality/NinePersonalQuality.vue`。
2. `其他看板`：跳转 `/personalQuality`，页面 `webapp/src/views/PageCodeWalkThroughInfo/PersonalQuality.vue`，且仅登录后展示。

因此质量看板不是新平台新增模块，两个页面都需要按老平台入口做二次对齐。

### 研发质量看板

老平台页面提供项目下拉：

- 默认项目：`CC2026R3`
- 候选来源：`getLabelPhase()`
- 用户切换项目后重新请求 `/quality/getAllQualityData`，并同步刷新 DGM 代码走查缺陷密度。

老平台主 KPI：

1. 需求评审缺陷密度
   - 公式说明：需求评审缺陷数 / 被评审需求文档页数。
   - 目标值：`[0.2, 0.6]`。
   - 点击跳转：评审数据页面。
2. 设计评审缺陷密度
   - 公式说明：设计评审缺陷数 / 被评审设计文档页数。
   - 目标值：`[0.2, 0.6]`。
   - 点击跳转：评审数据页面。
3. CC 代码走查缺陷密度
   - 公式说明：代码走查缺陷数 / 被走查代码千行数。
   - 目标值：内核 `[2,10]`，产品 `[5,12]`。
   - 点击动作：导出 `CC库-{项目}-代码走查数据`。
4. DGM 代码走查缺陷密度
   - DGM 项目名由 `CC2026R3` 转为 `CrownCAD 2026 R3` 这类格式。
   - 点击动作：导出 `DGM库-{项目}-代码走查数据`。
5. 集成测试通过率
   - 公式说明：通过的集成测试用例数 / 总的测试用例数。
   - 目标值：不低于 `90%`。
   - 点击跳转：集成测试数据页面。
6. 发布缺陷遗留率
   - 公式说明：系统缺陷遗留数 / 系统测试缺陷数。
   - 目标值：不超过 `15%`。
   - 点击跳转：其他看板的 `defect-leakage` tab。
7. 开发缺陷遗留率
   - 公式说明：集成测试缺陷数 /（集成测试缺陷数 + 系统测试缺陷数）。
   - 老平台提示文案写“不低于 90%”。
   - 点击跳转：其他看板的 `defect-elimination-rate` tab。
8. 新发缺陷修复率
   - 点击跳转：系统测试缺陷汇总。

老平台研发质量看板还展示以下图表入口：

1. 按走查人统计代码走查缺陷密度。
2. 按被走查人统计代码走查缺陷密度。
3. 按修复人统计缺陷数。
4. 代码提交频次。
5. 指派人剩余缺陷数量。

这些图表标题均可点击跳转到老平台相应多元看板或统计页 tab。

老平台接口依据：

- `GET /quality/getAllQualityData`
- `GET /quality/codeWalkthroughDefectDensity`
- DGM `GET /quality/codeWalkthroughDefectDensity`
- 代码走查全量导出接口：`downloadCCAllCodeThroughData`、`downloadDGMAllCodeThroughData`

### 其他看板

老平台 `PersonalQuality.vue` 使用 tabs 展示固定图表：

1. `功能缺陷数量`
2. `功能缺陷密度`
3. `质量达人榜`
4. `成员未修复缺陷率`
5. `发布缺陷遗留率`
6. `开发缺陷遗留率`

其中多个图表自带项目/阶段选择和下载按钮。例如：

- `FunctionDefectChart.vue`：级联选择测试阶段，导出 `{阶段}-功能缺陷数量统计`。
- `CodeQualityChart.vue`：项目下拉，导出 `{项目}质量达人榜统计`。
- `DefectLeakageRate.vue`：下载发布缺陷遗留率 Excel。
- `DefectEliminationRate.vue`：下载开发缺陷遗留率 Excel。

## 新平台现状

### 入口

新平台仍有两个入口：

1. `quality-board-rd-quality-board`：`/quality-board/rd-quality-board`
2. `quality-board-other-board`：`/quality-board/other-board`

`其他看板` 登录后展示，这一点与老平台一致。

### 研发质量看板

新平台 `QualityBoardRdView.vue` 当前展示：

1. 摘要卡片：
   - 需求评审缺陷密度
   - 设计评审缺陷密度
   - 代码走查缺陷密度(CC)
   - 代码走查缺陷密度(DGM)
   - 系统测试未关闭占比
2. 图表：
   - 评审密度对比
   - 代码走查密度
   - 系统测试模块修复率

数据来源为评审记录摘要、代码走查多元看板 overview、系统测试缺陷汇总统计板。

### 其他看板

新平台 `QualityBoardOtherView.vue` 当前展示：

1. 客户问题响应率
2. 客户问题功能热点
3. 代码走查责任人密度
4. 系统测试延期原因

这些图表更多是新平台重新设计的跨域辅助视图，与老平台 `PersonalQuality.vue` 的 tab 集合不一致。

## 已确认差异

### 1. 研发质量看板缺少项目下拉范围切换

**影响范围：高。影响所有 KPI 数值和图表范围。**

老平台在页面顶部提供项目下拉，默认 `CC2026R3`，切换后重新计算所有质量指标。

新平台研发质量看板没有项目选择入口，使用各子接口默认范围或各自内部默认值。用户无法复现老平台“按项目查看质量看板”的操作。

### 2. 研发质量看板核心 KPI 缺失

**影响范围：高。影响老平台已有指标可见性。**

新平台缺少老平台主 KPI：

1. 集成测试通过率。
2. 发布缺陷遗留率。
3. 开发缺陷遗留率。
4. 新发缺陷修复率。

新平台用“系统测试未关闭占比”替代了部分质量信号，但老平台没有这个同名主 KPI，不能作为 1:1 对齐替代。

### 3. 研发质量看板 KPI 口径可能不一致

**影响范围：高。影响同一数据下的展示值。**

老平台 `/quality/getAllQualityData` 对评审、代码走查、集成测试和系统测试指标使用统一 `projectName` 参数。

新平台需求/设计评审缺陷密度从评审记录列表摘要反推，代码走查缺陷密度取多元看板 overview，系统测试图表取系统测试缺陷汇总统计板。当前没有统一项目参数贯穿所有子查询，无法保证与老平台同项目口径一致。

### 4. CC / DGM 代码走查数据下载入口缺失

**影响范围：中到高。影响老平台已有操作入口。**

老平台点击 `CC代码走查缺陷密度` 和 `DGM代码走查缺陷密度` 标题会下载对应项目的全量代码走查数据。

新平台研发质量看板仅提供跳转到代码走查看板，没有等价下载入口。

### 5. 老平台研发质量看板下方 5 个专题图表缺失或不等价

**影响范围：高。影响页面内容集合。**

老平台研发质量看板展示：

1. 按走查人统计代码走查缺陷密度。
2. 按被走查人统计代码走查缺陷密度。
3. 按修复人统计缺陷数。
4. 代码提交频次。
5. 指派人剩余缺陷数量。

新平台研发质量看板只展示 3 张概览图，未等价展示以上图表。部分能力可能散落在代码走查多元看板或系统测试多元看板，但首页不可见，不能算入口等价。

### 6. 老平台主 KPI 的规则说明未完整保留

**影响范围：中。影响用户理解指标。**

老平台每个 KPI 旁有 tooltip，说明公式和目标值。新平台部分文案说明为概览性描述，没有逐项保留公式说明和目标阈值。

### 7. 老平台主 KPI 点击行为未完全对齐

**影响范围：中。影响入口可达性。**

老平台每个 KPI 标题有明确跳转或下载行为。新平台目前只有部分图表右上角链接，且行为不一致：

- 需求/设计评审密度：新平台跳转评审数据管理，可视为部分等价。
- 代码走查密度：新平台跳转代码走查看板，但不下载项目数据。
- 集成测试通过率、发布缺陷遗留率、开发缺陷遗留率、新发缺陷修复率：新平台缺少对应 KPI，自然也缺少点击入口。

### 8. 其他看板 tab 集合完全不一致

**影响范围：高。影响老平台已有页面内容。**

老平台其他看板是固定 tab 集合：

1. 功能缺陷数量
2. 功能缺陷密度
3. 质量达人榜
4. 成员未修复缺陷率
5. 发布缺陷遗留率
6. 开发缺陷遗留率

新平台其他看板展示客户问题响应率、客户问题功能热点、代码走查责任人密度、系统测试延期原因。除“代码走查责任人密度”与老平台部分代码走查视角相关外，整体不是同一个页面。

### 9. 其他看板缺少老平台图表内筛选和导出入口

**影响范围：高。影响操作窗口。**

老平台多个 tab 图表自带项目/阶段选择和下载按钮。新平台其他看板只有刷新和正式页跳转，缺少：

1. 功能缺陷数量阶段级联选择和导出。
2. 功能缺陷密度阶段级联选择和导出。
3. 质量达人榜项目选择和导出。
4. 发布缺陷遗留率导出。
5. 开发缺陷遗留率导出。

### 10. 其他看板当前混入客户问题能力，老平台无对应依据

**影响范围：中。影响“新平台有但老平台无”的功能清理判断。**

客户问题响应率和客户问题功能热点来自客户问题模块。老平台质量看板的其他看板没有这两张图。若保留，需要作为新平台增强能力单独审批，而不能算老平台对齐结果。

## 建议后续对齐顺序

1. 先裁定质量看板是否必须 1:1 还原老平台图表集合。按当前重构红线，默认应还原。
2. 研发质量看板先补项目范围选择，并让所有 KPI 使用同一项目参数。
3. 补齐研发质量看板 8 个主 KPI 和对应公式说明、目标阈值、颜色判定、点击行为。
4. 补齐 CC / DGM 项目代码走查数据下载入口。
5. 补齐研发质量看板下方 5 个专题图表，或明确这些图表在哪个新页面等价可达并在首页保留入口。
6. 其他看板改回老平台 6 个 tab，补齐图表内筛选和导出。
7. 当前新平台其他看板的客户问题类图表如需保留，应移到新平台增强区或等待产品审批。

## 本轮结论

质量看板模块二轮复核发现明显未对齐：新平台保留了两个入口名称，但页面内容和老平台差异较大。当前不能标记为“已对齐”，应进入待实现对齐状态。
