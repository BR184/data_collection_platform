# 代码走查非法数据页新旧平台差异记录

> 记录日期：2026-06-12；最近复核：2026-06-15
> 新平台：`D:\projects\data_collection_platform`
> 老平台：`D:\projects\spidergitdata-dev`
>
> 本文只记录会影响数据一致性、字段一致性或功能可达性的差异。分页默认值、UI 形态、筛选控件使用方式等不作为问题记录。

## 对齐目标

同一数据源、同一筛选条件下，新平台应与老平台保持：

1. 非法数据总数一致。
2. 命中的合并请求记录集合一致。
3. 表格字段及字段值一致。
4. 详情中能看到老平台展开行已有的关键字段。
5. 导出数据范围、字段含义和字段值一致。
6. 老平台能触发的关键数据刷新链路，新平台也能触发。

## 本轮已修正

### 1. 查询范围口径

已按老平台代码走查非法数据默认范围对齐：

- `deleted = false`
- `merge_request_state = 'merged'`
- `merged_at_source > 2024-04-01 00:00:00`
- `module_name <> 无需标注`
- CrownCAD / DGM / default 源在未指定目标分支时默认按 `dev` 查询

### 2. 非法类型判定

已将新平台非法类型判定和老平台底层规则对齐：

- 未标注项目名
- 未标注模块名
- 代码走查异常
- 未进行代码扫描
- 静态扫描问题未关闭
- 代码注释量未达标
- 静态扫描失败
- 注释率分析工具Clang分析错误
- GitLab 接口报错

同时兼容老平台下拉筛选里出现过的别名：

- `未标注项目名称` -> `未标注项目名`
- `未标注模块名称` -> `未标注模块名`
- `无代码走查` -> `代码走查异常`
- `未代码扫描` -> `未进行代码扫描`

这样可以保证页面筛选语义不丢，同时非法记录展示仍保持底层真实值。

2026-06-15 复核补充：老平台下拉筛选项是 `无代码走查`，但列表实际非法类型显示由 `CODE_REVIEW_EXCEPTION_DESCRIPTION` 生成，为 `代码走查异常`。新平台已按该行为拆分筛选值和展示值。

2026-06-15 复核补充：老平台 CC/default 默认非法总数不把“仅命中 Clang 注释率分析错误”的记录纳入；DGM 默认非法查询会纳入 Clang。新平台 SQL 分页路径、内存路径、规则说明和规则预览基线已按 `source_instance` 对齐该口径；显式筛选 `注释率分析工具Clang分析错误` 仍可查询。

2026-06-15 复核补充：老平台 `GitLab 接口报错` 只检查扫描结果、目标分支和走查人字段；不检查“被指派人”。新平台已按老平台字段语义收窄，避免仅被指派人异常导致非法总数偏大。

### 3. 采集/外部指标/事实层字段

已把老平台 `ExcelBo` / `SpiderCrowncadData` 中会影响展示和导出的字段补入外部指标表与 `merge_request_fact`：

- 删除走查代码行数
- 规范类/逻辑类/性能类/设计类/其他类缺陷数
- 代码走查速率 LOC/H、KLOC/H
- 代码走查缺陷密度
- 代码走查效率
- 提交次数、提交频率
- 功能名称
- Clang-tidy 解析新增代码行数

事实构建优先使用外部指标值；外部指标缺失时按老平台代码中的公式兜底计算。

### 4. 表格、详情和筛选字段

主表和详情已按老平台字段语义展示：

- `被走查人` 使用 MR author。
- `走查人` 使用 reviewer names。
- `被指派人` 使用 assignee names。
- `合并人` 使用 merge user。

条件筛选里的“被走查人”也按 author 查询；SQL 路径和内存路径均支持拼音/首字母搜索。

2026-06-15 复核补充：老平台“走查人”字段来自代码走查评论/表单解析结果（旧表 `assignee`），不是 GitLab reviewer。新平台事实构建已优先把 `collect_form_records.reviewer` 写入 `merge_request_fact.reviewer_names`，表单没有时才回退 GitLab reviewers，保证列表、详情和导出中的“走查人”字段优先遵从老平台语义。

### 4.1 走查解析异常细分

老平台把以下走查解析异常写入旧表 `assignee`，页面统一显示为 `代码走查异常`：

- `没有合法评论`
- `代码走查时间或缺陷数异常`
- `代码走查标题异常`
- `代码走查记录行数异常`

新平台已新增 `merge_request_fact.review_exception_reason`，在事实构建时基于本地镜像 MR 评论复刻上述异常原因，并让 `reviewer_names` 优先展示老平台“走查人/assignee”语义值：解析出的走查人、上述异常原因、`无需走查` 或 `无需走查扫描`。默认非法判定、规则配置预览、列表、详情和导出均从事实字段读取，不再只靠页面层文案替代。

### 5. 导出结构

已切换为 XLSX 导出，并按老平台 `ExcelBo` 表头顺序生成 `非法代码走查数据` sheet。非 CrownCAD / DGM 的场景保留额外 `全量代码走查数据` sheet。

2026-06-15 复核补充：老平台 DGM 导出接口请求不传 `name`，因此只导出 `非法代码走查数据` sheet，不附加 `全量代码走查数据`。新平台已按该行为收敛：仅当显式选择非 `CrownCAD` 的项目名时，才附加全量 sheet。

### 6. 单条 MR 刷新

已补齐单条合并请求事实刷新接口和页面行操作，按当前源实例、项目 ID、MR IID 重建单条事实记录后刷新当前表格。

### 7. 走查时间来源

已补齐老平台展开行和 Excel 导出中的独立 `走查时间` 字段：

- `merge_request_fact.code_walkthrough_date` 作为事实层字段保存。
- 来源优先取 MR 评论中包含 `## 代码走查数据` 的走查评论更新时间。
- 如果没有合法走查评论，回退到新平台走查表单更新时间。
- 如果仍取不到，回退到 MR 更新时间，保持老平台解析不到走查评论时的兜底语义。
- 页面详情展示 `走查时间`，Excel 导出第一列使用 `走查时间`，不再用 `合并时间` 代替。
- 老平台 `SpiderCrowncadData.codeWalkthroughDate` 和 `ExcelBo(SpiderCrowncadData)` 按 `yyyy-MM-dd` 展示/导出。新平台详情页走查时间和 Excel 第一列已改为日期格式，合并时间仍保留 `yyyy-MM-dd HH:mm:ss`。

### 8. MR 链接 source_instance

已补齐代码走查非法数据行的 `sourceInstance` 响应字段，并在生成 MR 链接时传入 `source_instance`。这样 DGM 或其他源实例不再退回默认源项目路径猜测，避免同 IID 跳到错误 GitLab 项目。

### 9. 集成测试主模块删除

已删除新平台运行时的集成测试主模块入口：

- 前端页面、路由和 QualityBoard 入口已删除。
- 后端 `/api/integration-tests` 控制器、查询、导出、事实构建服务和响应实体已删除。
- 事实刷新任务不再入队或执行 `INTEGRATION_TEST`。
- 源健康页不再展示 `集成测试事实`。
- 新增迁移删除旧 `integration_test_fact` 表，当前 `schema.sql` 也不再建该表。

保留项：`IssueLabelRules` 中的“集成测试”仍作为历史测试阶段标签识别关键字存在，这不是集成测试主模块入口。

## 仍需产品/环境确认

### 1. MR 链接多 GitLab host

新平台已按 `source_instance` 查对应镜像项目路径生成 MR 链接。仍需线上环境确认的是：如果同一平台内多个 GitLab host 不共享 `GITLAB_WEB_BASE_URL`，需要继续把 GitLab host 纳入 source instance 或项目 URL 映射配置。

### 2. 定时任务执行时间和执行时长

老平台展示 `任务执行时间` 和 `执行时长`。新平台目前展示实时工作区刷新状态和事实刷新结果，但没有在代码走查非法数据页 1:1 展示老平台任务执行时长字段。该项不影响列表记录集合和字段值，但影响用户判断数据批次。

## 明确不记录为问题的差异

- 分页默认页大小不同。
- UI 组件形态不同，例如 tab 与分段控件。
- 筛选条件入口或交互方式不同，只要筛选语义和结果一致即可。
- 新平台额外提供规则说明、规则配置、统一条件构造器等新能力。
