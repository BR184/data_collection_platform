# 代码走查非法数据页新旧平台差异记录

> 记录日期：2026-06-12
> 新平台：`D:\projects\data_collection_platform`
> 老平台：`D:\projects\spidergitdata-dev`
>
> 本文只记录会影响数据一致性、字段一致性或功能可达性的差异。分页默认值、UI 形态、筛选控件使用方式等不作为问题记录。

## 对齐目标

同一数据源、同一筛选条件下，新平台应与老平台保持：

1. 非法数据总数一致。
2. 命中的合并请求记录集合一致。
3. 表格字段及字段值一致。
4. 详情中能看到老平台展开行已有的关键字段。
5. 导出数据范围、字段含义和字段值一致。
6. 老平台能触发的关键数据刷新链路，新平台也能触发。

## 本轮已修正

### 1. 查询范围口径

已按老平台代码走查非法数据默认范围对齐：

- `deleted = false`
- `merge_request_state = 'merged'`
- `merged_at_source > 2024-04-01 00:00:00`
- `module_name <> 无需标注`
- CrownCAD / DGM / default 源在未指定目标分支时默认按 `dev` 查询

### 2. 非法类型判定

已将新平台非法类型对齐老平台规则标签：

- 未标注项目名
- 未标注模块名
- 无代码走查
- 未进行代码扫描
- 静态扫描问题未关闭
- 代码注释量未达标
- 静态扫描失败
- 注释率分析工具Clang分析错误
- GitLab 接口报错

SQL 下推和 Java 规则注册表使用同一组标签，避免列表总数和页面二次筛选结果不一致。

### 3. 采集/外部指标/事实层字段

已把老平台 `ExcelBo` / `SpiderCrowncadData` 中会影响展示和导出的字段补入外部指标表与 `merge_request_fact`：

- 删除走查代码行数
- 规范类/逻辑类/性能类/设计类/其他类缺陷数
- 代码走查速率 LOC/H、KLOC/H
- 代码走查缺陷密度
- 代码走查效率
- 提交次数、提交频率
- 功能名称
- Clang-tidy 解析新增代码行数

事实构建优先使用外部指标值；外部指标缺失时按老平台代码中的公式兜底计算。

### 4. 表格、详情和筛选字段

主表和详情已按老平台字段语义展示：

- `被走查人` 使用 MR author。
- `走查人` 使用 reviewer names。
- `被指派人` 使用 assignee names。
- `合并人` 使用 merge user。

条件筛选里的“被走查人”也按 author 查询；SQL 路径和内存路径均支持拼音/首字母搜索。

### 5. 导出结构

已切换为 XLSX 导出，并按老平台 `ExcelBo` 表头顺序生成 `非法代码走查数据` sheet。非 CrownCAD / DGM 的场景保留额外 `全量代码走查数据` sheet。

### 6. 单条 MR 刷新

已补齐单条合并请求事实刷新接口和页面行操作，按当前源实例、项目 ID、MR IID 重建单条事实记录后刷新当前表格。

## 仍需产品/环境确认

### 1. MR 链接多 GitLab host

老平台区分 DGM、CrownCAD 和其他 CC 项目的 GitLab host。新平台当前按统一资源链接服务生成链接；如果线上确有多个 GitLab host，需要按 source instance 或项目 URL 映射继续细化。

### 2. 定时任务执行时间和执行时长

老平台展示 `任务执行时间` 和 `执行时长`。新平台目前展示实时工作区刷新状态和事实刷新结果，但没有在代码走查非法数据页 1:1 展示老平台任务执行时长字段。该项不影响列表记录集合和字段值，但影响用户判断数据批次。

## 明确不记录为问题的差异

- 分页默认页大小不同。
- UI 组件形态不同，例如 tab 与分段控件。
- 筛选条件入口或交互方式不同，只要筛选语义和结果一致即可。
- 新平台额外提供规则说明、规则配置、统一条件构造器等新能力。
