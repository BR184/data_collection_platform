# 代码走查非法数据页新旧平台差异记录

> 记录日期：2026-06-12
> 新平台：`D:\projects\data_collection_platform`
> 老平台：`D:\projects\spidergitdata-dev`
>
> 本文只记录会影响数据一致性、字段一致性或功能可达性的差异。分页默认值、UI 形态、筛选控件使用方式等不作为问题记录。

## 对齐目标

同一数据源、同一筛选条件下，新平台应与老平台保持：

1. 非法数据总数一致。
2. 命中的合并请求记录集合一致。
3. 表格字段及字段值一致。
4. 详情中能看到老平台展开行已有的关键字段。
5. 导出数据范围、字段含义和字段值一致。
6. 老平台能触发的关键数据刷新链路，新平台也能触发。

## 有效差异

### 1. 查询范围口径不一致

老平台代码走查非法数据默认只查：

- `status = MERGED`
- 合并时间大于 `2024-04-01 00:00:00`
- `module_name != 无需标注`
- 目标分支通过 `getDevBranch(name, targetBranch)` 做旧平台分支归一化

新平台当前非法数据查询从 `merge_request_fact where deleted = false` 出发，没有等价限制。这个差异会直接导致非法数据总数和记录集合不同。

### 2. 非法类型判定不一致

老平台非法类型枚举为：

- 未标注项目名称
- 未标注模块名称
- 无代码走查
- 未代码扫描
- 静态扫描问题未关闭
- 代码注释量未达标
- 静态扫描失败
- 注释率分析工具Clang分析错误
- GitLab 接口报错

老平台列表展示中还会把部分走查解析异常聚合显示为 `代码走查异常`。

新平台当前非法类型为：

- 缺少模块标签
- 缺少标注责任人
- 无代码走查
- 未代码扫描
- 静态扫描问题未关闭
- 缺少代码注释比例
- 缺少缺陷数量
- 缺少新增代码行数

该差异会导致非法类型下拉、命中规则、列表展示和导出值均不一致。

### 3. 事实层缺少老平台扫描/注释率结果字段

老平台依赖以下字段判定非法类型：

- `sonar_qube_result`
- `annotation_rate_result`
- `bug_count_result`
- `annotation_rate`
- `bug_count`

新平台 `merge_request_fact` 当前有 `scan_status`、`scan_bug_count`、`comment_rate`、`defect_count`，但事实构建中 `scan_status` 和 `scan_bug_count` 暂时写空，且没有承载 `annotation_rate_result`、`bug_count_result` 的等价字段。

该差异会导致 `未代码扫描`、`静态扫描问题未关闭`、`代码注释量未达标`、`静态扫描失败`、`注释率分析工具Clang分析错误` 等老平台非法数据无法完整复现。

### 4. 表格字段语义不一致

老平台主表字段包括：

- 合并请求编号
- 合并请求内容
- 被走查人
- 所属项目
- 合并时间
- 合并人
- 模块名
- 合并目标分支
- 非法类型
- 代码注释比例(%)
- 缺陷数量
- 新增代码行数(行)

新平台当前把老平台的 `被走查人 author` 位置替换为 `标注责任人 owner`。事实构建中的 `owner` 来自 reviewer 优先、assignee 兜底，不等价于老平台 `author`。

该差异会导致同一行展示给用户的人员字段不一致。

### 5. 详情字段缺失

老平台展开行可查看：

- 走查编号
- 所属项目
- 走查时间
- 模块名
- 被走查人
- 走查人
- 被指派人
- 合并时间
- 合并人
- 合并目标分支
- 走查工作量（分钟）
- 新增走查代码行数（LOC）
- 缺陷数（个）
- 代码走查速率（LOC/H）
- 代码走查缺陷密度（个/KLOC）
- 代码走查效率（个/H）

新平台详情抽屉当前只展示基础信息、非法判定和三个度量指标。缺少走查人、被指派人、走查时间、走查耗时、走查速率、缺陷密度、效率等老平台已有字段。

### 6. 导出字段和文件结构不一致

老平台导出 XLSX，`非法代码走查数据` sheet 使用 `ExcelBo` 完整字段，包含走查、缺陷分类、扫描、注释率、效率等字段。非 CrownCAD 项目还会额外导出 `全量代码走查数据` sheet。

新平台当前导出 CSV，仅包含请求类型、MR、项目、仓库、模块、责任人、目标分支、合并人、合并时间、非法类型、评论率、缺陷数、新增行数、标题、链接。

该差异会导致导出无法承接老平台使用场景。

修正记录：已将新平台导出切换为 XLSX，并按老平台 `ExcelBo` 表头顺序生成 `非法代码走查数据` sheet；DGM 或非 CrownCAD 项目会额外生成 `全量代码走查数据` sheet。当前事实层尚未承载老平台所有细分字段，删除行数、缺陷分类、提交次数、提交频率、功能名称等列先保留表头并按空值或 0 输出，后续若要做到字段值完全一致，需要继续把这些字段从采集/外部指标层补入 `merge_request_fact`。

### 7. 单条合并请求刷新能力缺失

老平台每行支持按 `issuableReference + dataSource` 刷新单条合并请求数据，并刷新当前页。

新平台当前只有页面级“刷新最新数据”，会刷新镜像表并重建事实表，不能等价替代单条 MR 修正链路。

修正记录：已新增单条合并请求事实刷新接口和页面行操作，按当前源实例、项目 ID、MR IID 重建单条事实记录后刷新当前表格。

### 8. MR 链接生成对多 GitLab host 不够明确

老平台：

- DGM 使用 DGM GitLab 地址
- CrownCAD 使用 CrownCAD 固定地址
- CC 其他所属项目使用项目 URL 映射

新平台当前用统一 `platform.gitlab-mirror.web-base-url` 拼接项目路径。若 CC 和 DGM 确实来自不同 GitLab host，同一数据源下链接会不一致。

### 9. 定时任务执行时间和执行时长缺失

老平台展示 `任务执行时间` 和 `执行时长`。新平台当前只展示实时工作区最后同步时间。该差异不一定影响列表数据，但影响用户判断本页数据采集结果是否与老平台同一批次。

## 明确不记录为问题的差异

- 分页默认页大小不同。
- UI 组件形态不同，例如 tab 与分段控件。
- 筛选条件入口或交互方式不同，只要筛选语义和结果一致即可。
- 新平台额外提供规则说明、规则配置、统一条件构造器等新能力。
