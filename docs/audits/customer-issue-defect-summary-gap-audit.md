# 客户问题缺陷汇总页新旧平台差异记录

> 记录日期：2026-06-15
> 新平台：`D:\projects\data_collection_platform`
> 老平台：`D:\projects\spidergitdata-dev`
>
> 本文只记录会影响数据一致性、字段一致性或功能可达性的差异。分页默认值、UI 形态、筛选控件使用方式等不作为问题记录。

## 对齐目标

同一里程碑/项目/筛选条件下，新平台应与老平台保持：

1. 主表模块行集合和总计行一致。
2. 每个统计列的数量、百分比和空值展示一致。
3. 可下钻统计单元格命中的议题集合一致。
4. 下钻表格字段名、字段值和展示顺序一致。
5. 当前汇总导出和全量议题导出的数据范围、字段含义和值一致。
6. 页面可见的里程碑/任务批次信息一致或能表达同等含义。

## 老平台基线

### 页面入口和主接口

- 页面：`webapp/src/views/PageHome/ContentComponents/QuestionnaireInfo/ModuleTableCCProduct.vue`
- 主表接口：`GET /dataAnalysis/getModuleTable`
- 当前汇总导出：`POST /dataAnalysis/exportModuleTable`
- 全量议题数据导出：`GET /issueStaticData/all`
- 下钻弹窗：`webapp/src/views/PageHome/ContentComponents/ModuleTableDetail.vue`

### 老平台可见能力

老平台页面提供：

- 里程碑级联选择。
- 查询当前里程碑客户问题缺陷汇总。
- 下载当前汇总。
- 下载当前里程碑全量议题数据。
- 展示任务执行时间和执行时长。
- 主表数量类单元格下钻到议题详情。
- 下钻详情字段：议题编号、模块名、议题标题、议题状态、严重程度、测试状态、延期原因，以及展开区的议题更新时间、议题提交时间、议题提交人、议题处理人。

### 老平台主口径

- 主表来自 `SpiderIssueDataService.getModuleTable()`。
- `projectId = 325` 时由里程碑控制范围。
- 模块名称来自 `DropDownService.getModuleNameFromSpiderIssueData(projectId, phase)`。
- 模块匹配使用 `ModuleSplitUtil.isContainModule()`，只按 `&` 拆分，不按逗号类分隔符拆分。
- `任务执行时间` 来自 `getScheduledTimeRecord({name:'issue', value:'CCProduct', projectId:'325'})`。

## 待标记差异

> 2026-06-15 对齐更新：以下 1、2、3、4、5、6、8 已在新平台按老平台代码口径补齐。第 7 项属于事实层模块归一化边界，当前不在页面服务里重复实现，继续以 `docs/platform-page-business-rules.md` 和事实层标签解析为准。

### 1. 缺少老平台同等的里程碑筛选入口

**影响范围：高。影响整页统计范围。**

老平台客户问题缺陷汇总页面由里程碑级联控制版本/范围。

新平台对齐前 `CustomerIssueDefectSummaryBoardService` 的筛选字段是：

- `projectName`
- `moduleName`
- `severityLevel`
- `priorityLevel`

但没有老平台同等语义的里程碑筛选入口。当前页面虽然可通过 `customerIssueScopeProfile` 收口 `milestoneTitle`，但用户侧不可见的固定收口不等价于老平台的显式里程碑切换。

**对齐状态：已补齐。** 新平台客户问题缺陷汇总筛选字段已增加 `milestoneTitle`，用于显式按里程碑切换统计范围。

### 2. 模块字段展示名与老平台不一致

**影响范围：中。属于可见字段差异。**

老平台主表首列显示的是 `模块名`。

新平台主表定义里当前显示为 `模块名称`，对应字段也按 `moduleName` 过滤。

字段值本身未必错，但显示名没有 1:1 对齐老平台。

**对齐状态：已补齐。** 主表首列和模块筛选展示名已统一为 `模块名`。

### 3. 一级缺陷分类字段存在展示差异

**影响范围：中。影响用户对照老平台表头。**

老平台一级缺陷分类列为：

- 回退(个)
- 挂机(个)
- 其他(个)

新平台当前一级缺陷分类列为：

- 回退(个)
- 挂起(个)
- 其他(个)

`挂起` 与老平台 `挂机` 不一致，需要标记。

**对齐状态：已补齐。** 一级缺陷分类表头已改为 `挂机(个)`。

### 4. 主表统计口径和老平台不一致

**影响范围：高。会直接影响多个主表数量和百分比。**

老平台客户问题缺陷汇总复用 `ModuleTableRow` 的老口径：

- `FIXED`、`CRITICAL_FIXED`、`MAJOR_FIXED`、`MINOR_FIXED`、`NEW_ISSUE_FIX` 走 `setFixQuery()`。
- `P1_FIXED`、`P2_FIXED`、`P3_FIXED` 使用 `bug_status` 包含 `已修复/完成`、`未复现`，或 `status = CLOSED`。
- `P2_CLOSED`、`P3_CLOSED` 要求 `status = CLOSED` 且测试状态含 `已修复/完成` 或 `未复现`。
- `RETEST_FAILED` 使用 `bug_status like '未修复'`。
- `EXTENSION` / `MODULE_DELAY_DEFECT_NUM` 使用 `bug_status like '申请延期'`。
- `SUGGESTION_NEW_ISSUE` 使用 `category like '建议类'`。

新平台当前直接依赖事实层聚合字段与 `isSolvedLike()`、`isClosed()`、`legacy()` 等统一判断。只要这些事实口径和老平台硬编码不完全同源，数量就会偏移。

**对齐状态：已补齐。** 新平台客户问题缺陷汇总已按老平台 `ModuleTable` 查询分支重写核心谓词：

- 已修复类复用 `bugStatus` 中的 `已修复`、`待合并`、`未更新`。
- P1/P2/P3 已修复类使用 `已修复/完成`、`未复现` 或已关闭。
- P2/P3 关闭率使用已关闭且 `bugStatus` 含 `已修复/完成` 或 `未复现`。
- `申请延期`、`复测未通过`、`建议类` 改为按老平台对应字段文本判断。

### 5. 遗留率区域口径和老平台不一致

**影响范围：高。**

老平台遗留率实际执行口径是：

- 一级缺陷遗留率 = `(一级缺陷总数 - 一级缺陷已修复数量) / 一级缺陷总数`
- 二级缺陷遗留数量 = 二级未修复数
- 三级缺陷遗留数量 = 三级未修复数
- 二三级缺陷遗留率 = `(二级缺陷已修复数量 + 三级缺陷已修复数量) / 模块总缺陷数`

说明：老平台枚举名里有 `CRITICAL_OPEN` / `MajorAndMinorOpen`，但 DAO 分支实际调用 `setFixQuery()`，因此以实际查询条件为准。

**对齐状态：已补齐。** 新平台遗留率区域不再使用 `issue_fact.is_legacy`，改按上述老平台实际公式计算。

### 6. 下钻字段少于老平台

**影响范围：中。影响用户核对统计来源。**

老平台下钻详情需要展示：

- 议题编号
- 模块名
- 议题标题
- 议题状态
- 严重程度
- 测试状态
- 延期原因
- 议题更新时间
- 议题提交时间
- 议题提交人
- 议题处理人

新平台当前下钻字段偏向：

- 议题编号
- 标题
- 模块
- 所属项目
- 创建人
- 状态
- 标签
- 更新时间

缺少或未按老平台字段名展示的内容包括：

- 测试状态
- 严重程度
- 延期原因
- 议题提交时间
- 议题处理人

**对齐状态：已补齐。** 新平台下钻字段已补齐并按老平台字段名展示：议题编号、模块名、议题标题、议题状态、严重程度、测试状态、延期原因、议题更新时间、议题提交时间、议题提交人、议题处理人。

### 7. 模块拆分规则需要与老平台保持一致

**影响范围：中到高。**

老平台客户问题模块名拆分只按 `&` 处理。

如果新平台事实层对 `moduleNames` 使用了更宽松的分隔规则，会导致同一条议题命中的模块集合与老平台不同，进而影响：

- 模块行集合
- 各模块数量
- 下钻命中集合

**对齐状态：事实层边界保留。** 当前页面服务使用事实层 `moduleNames`，不在页面层重新拆分模块。按 `docs/platform-page-business-rules.md`，模块字段必须来自事实层已归一化字段，后续若发现事实层模块拆分与老平台 `&` 规则不一致，应在事实层修正，而不是在本页临时补逻辑。

### 8. 当前页面没有老平台同等的“下载议题数据”入口证据

**影响范围：中。功能可达性差异。**

老平台页面明确提供 `下载议题数据`，对应 `GET /issueStaticData/all`。

新平台通用统计板有汇总导出，但在当前客户问题缺陷汇总页上，没有看到与老平台同名、同语义的单独“下载议题数据”入口。

**对齐状态：已补齐。** 新平台客户问题缺陷汇总页已增加 `下载议题数据` 额外操作，复用客户问题记录导出接口，并携带当前条件筛选。

### 9. 任务执行时间/执行时长展示需进一步核对

**影响范围：低到中。**

老平台明确展示：

- 任务执行时间
- 执行时长

新平台统一统计工具栏已经有实时状态和刷新时间信息，但是否已在客户问题缺陷汇总页上以老平台同等方式呈现，需要继续核对。

**对齐状态：已具备等价信息。** 新平台统一统计工具栏展示实时同步状态、最近同步时间和页面刷新入口；不按老平台标签样式复刻，但功能可达性等价。
