## 老平台能力清单

### 页面筛选

老平台顶部直接提供以下筛选入口：

1. 标题：输入框，输入时触发查询，语义为标题模糊匹配。
2. 项目：可搜索下拉，来自已入库评审记录 `projectName` distinct，查询语义为精确匹配。
3. 模块：可搜索下拉，来自已入库评审记录 `moduleName` distinct，查询语义为精确匹配。
4. 负责人：可搜索下拉，来自已入库评审记录 `reviewCharger` distinct，查询语义为负责人模糊匹配。
5. 评审类型：固定枚举，包含需求说明书评审、设计说明书评审、产品用户手册、项目计划评审、其他，查询语义为精确匹配。
6. 问题状态：固定枚举，包含新提交、已修复、已关闭、已拒绝、无问题、未评审；先查问题明细，再反查评审记录。
7. 评审专家：人员下拉；先查问题明细，再反查评审记录。

### 主表字段

老平台主表展示：

- 标题
- 项目
- 问题合计(个)
- 页数
- 评审缺陷密度(个/页)
- 评审效率(个/小时)
- 评审速率(页/小时)
- 模块
- 负责人
- 上传时间
- 独立评审工作量合计(小时)
- 有效的独立评审问题数合计(个)
- 会议评审工作量(小时）
- 有效的会议评审问题数合计(个)
- 不达标说明
- 是否达标，提示口径为“评审缺陷密度介于[0.2~0.6]”

### 展开的问题清单

老平台行展开后展示评审问题清单，并支持新增、编辑、删除问题详情：

- 评审专家
- 评审工作量
- 评审类别：走查、独立评审、会议评审
- 在文档中的位置
- 问题类别：文档规范、完整性、功能性、可行性、无问题
- 问题描述
- 建议解决方案
- 责任人
- 不接受理由
- 问题状态
- 更新日期

### 主记录新增/编辑

老平台新建评审字段：

- 项目名称、标题、模块、评审类型、评审日期、评审负责人、评审专家(多选)、评审规模(页)、评审的工作产品、作者、评审版本。
- 保存后会为每个评审专家生成一条“未评审”问题项，并引导继续录入评审问题。

老平台编辑评审字段：

- 项目名称、标题、模块、评审类型、评审日期、评审负责人、评审规模(页)、评审的工作产品、作者、评审版本、不达标说明。

### 导出和导入

老平台提供：

- 导出评审列表：按项目、模块、标题、负责人、评审类型导出。
- 行级导出问题详情：按评审记录 id 导出。
- 查询条件导出问题详情：接口存在，但主页面没有直接按钮。
- 评审文件导入与模板下载：旧平台上传的是“单个评审文件模板”，不是评审列表导出的汇总文件。

## 新平台现状

### 已等价覆盖

1. 主表字段基本覆盖老平台字段，并额外展示评审类别、文档规范/完整性/功能性/可行性计数、原文件等辅助字段。
2. 行级问题清单、问题新增、编辑、删除和行级导出问题详情均可达。
3. 新建和编辑评审记录字段覆盖老平台字段；新增时可生成待录入问题项。
4. 评审类型、评审类别、问题类别、问题状态固定枚举与老平台一致。
5. 导出评审列表和导出问题列表均可达。
6. 老平台“模板”下载入口已恢复；新平台提供 `/api/review-data/template`，页面按钮下载文件名与老平台保持为 `模板文件.xls`。

### 新平台增强但不应改变老平台口径

1. 关键字搜索和高级条件筛选比老平台更强，允许覆盖更多字段；这可以作为体验增强保留，但不能改变老平台直接筛选字段的结果语义。
2. 设置按钮、固定视图、自动刷新开关属于新平台通用体验能力，不是老平台业务口径。
3. 详情抽屉和规则说明是新平台增强入口，可以保留。
4. 旧平台列表 Excel 导入向导是迁移能力；它不替代老平台“模板下载”入口，因此模板下载按老平台能力单独维护。

## 已对齐差异

### 1. 项目和模块直接筛选语义按老平台收紧

- 老平台：项目、模块使用精确匹配；标题、负责人使用模糊匹配。
- 新平台已改为：项目、模块、评审类型、问题状态、评审专家为精确匹配；标题和负责人保留模糊匹配。
- 高级筛选中的“包含”仍可表达模糊匹配，不改变老平台直接筛选入口语义。

### 2. 主表默认列收敛到老平台可见字段

- 新平台默认主表已移除非老平台默认列：评审类别、文档规范、完整性规范、功能性规范、可行性规范、原文件。
- 这些增强字段仍保留在详情、导出和底层响应中，不删除数据能力。

### 3. 导出列按老平台 DTO 对齐

- `导出评审列表` 已按旧平台 `ExportReviewDTO` 的列名和顺序输出。
- `导出问题详情` 已按旧平台 `ReviewProblemDTO` 的聚合统计口径输出，不再导出主记录 + 每条问题明细的展开表。
- 后续真实链路测试仍需下载文件并抽查表头和样例数据。

### 4. 模板下载入口按老平台恢复，导入迁移能力保持独立

- 老平台导入：上传旧平台模板评审文件，支持获取模板。
- 新平台已恢复：页面“模板”按钮调用 `/api/review-data/template` 下载旧平台同类评审模板工作簿，浏览器下载文件名为 `模板文件.xls`。
- 新平台导入：上传旧平台列表导出的 Excel，先预览后确认入库。这是迁移能力，不替代模板下载，也不改变当前导入链路。
- 后续如果业务要求恢复“按模板填报后直接导入单个评审文件”，需单独对齐旧平台上传解析链路，不能把迁移导入和模板导入混成一个入口。

### 5. 新增评审后的“保存,去录入评审问题”路径已恢复

- 老平台按钮文案直接是“保存,去录入评审问题”，保存后会立即打开问题录入。
- 新平台创建成功后先刷新列表，再展开新记录并打开新增评审问题弹窗。
- 后端原本已有按评审专家生成“未评审”待办问题项的能力，本次前端补齐操作闭环。

## 当前结论

评审数据管理主体能力已经覆盖老平台。本次已将已确认差异按老平台口径完成代码对齐：

1. 直接筛选语义恢复老平台精确/模糊边界。
2. 主表默认列恢复老平台可见列。
3. 导出评审列表和问题详情恢复老平台 DTO 列口径。
4. 新建评审后恢复“保存后继续录入评审问题”的操作闭环。
5. 模板下载入口按老平台恢复，页面按钮可下载 `模板文件.xls`。

验证结果：

1. 冒烟测试：前端 `npm.cmd run typecheck` 已通过；后端 `mvn -q -DskipTests compile` 已通过。
2. API 真实链路：登录 admin 后，列表查询、项目精确筛选、模块精确筛选、导出评审列表、导出问题列表、模板下载均已打通；模板接口返回 `application/vnd.ms-excel`，文件头为 `.xls` OLE 签名。
3. 浏览器真实链路：访问 `/#/review-data/home` 后确认管理员模式、老平台主表列、`模板` 按钮和 `新增评审` 可见；点击模板下载得到 `模板文件.xls`；新增评审保存后自动打开“新增评审问题”弹窗；临时测试数据已清理；浏览器控制台无错误。

当前结论：评审数据 / 评审数据管理已完成本轮按老平台功能口径的二次对齐。剩余可讨论项是“是否恢复旧平台单个模板文件导入解析”，该能力不同于当前迁移导入，也不同于本次已恢复的模板下载，需业务方单独确认后再实现。
