# 系统测试非法数据页新旧平台差异记录

> 记录日期：2026-06-15  
> 新平台：`D:\projects\data_collection_platform`  
> 老平台：`D:\projects\spidergitdata-dev`
>
> 本文只记录会影响数据一致性、字段一致性、可达性和非法判定口径的差异。分页默认值、UI 形态和普通交互差异不作为问题记录。

## 对齐目标

同一测试阶段/筛选条件下，新平台应与老平台保持：

1. 非法数据总数一致。
2. 非法类型行和筛选结果一致。
3. 主表字段、详情字段、字段值和展示顺序一致。
4. 导出字段和导出数据一致。
5. 默认进入页的统计范围一致。
6. 规则说明与实际非法判定一致。

## 老平台基线

### 页面入口和主接口

老平台对应页面：

- `webapp/src/views/PageStandard/IllegalIssueSearch.vue`

相关接口：

- `POST /issueStaticData/getIllegalIssue`
- `GET /getDownLabel/getIssueIllegalType`
- `GET /issueStaticData/exportIssue`
- 单条刷新：`updateIssueByProjectIdAndIssueId`

### 老平台非法类型

来自 `IssueIllegalTypeEnum` / `IllegalTypeList`：

- 未设定严重程度
- 未设定模块
- 未按照模板回复
- 缺陷原因不唯一

### 老平台主表和详情字段

主表可见字段：

- 议题编号
- 模块名
- 议题标题
- 议题状态
- 严重程度
- 议题处理人
- 非法类型

展开详情可见字段：

- 议题更新时间
- 议题提交时间
- 模块名
- 功能名
- 议题编号
- 议题标题
- 议题提交人
- 议题处理人
- 议题状态
- 测试状态
- 议题严重程度

### 老平台核心口径

1. `phaseName` 来自 `getLabelPhase()`，页面创建时默认取列表第一项。
2. `getIllegalIssue` 默认项目固定为 `9`（CrownCAD）。
3. 非法查询条件本质上是 `illegal_list is not null`，再按 `illegal_list like <非法类型>` 过滤。
4. `illegal_list` 是多值字符串，单条议题可能同时包含多个非法类型。
5. 页面提供单条议题刷新按钮，可重新拉取当前条数据。

## 已确认接近一致的部分

1. 新平台非法类型已收束为 4 类，并保留老平台同名文案。
2. 新平台规则说明已改为基于 `issue_fact.illegal_reason` 的事实层解释。
3. 新平台已有导出、规则说明、详情抽屉和实时状态。
4. 新平台已把 `未设定模块`、`未设定严重程度` 等支持项纳入非法原因归一化。

## 待标记差异

### 1. 默认统计范围不一致

**影响范围：高。影响首屏总数和下拉选项。**

老平台页面默认只看 CrownCAD 项目 `9`。  
新平台当前 `SystemTestIllegalRecordsView` / `SystemTestIllegalRecordService` 没有把页面默认范围绑定到固定项目，默认会按系统测试事实层范围取全量项目。

这会导致同一测试阶段下，首屏总数和非法数据集合与老平台不一致。

### 2. 默认测试阶段不一致

**影响范围：高。影响首屏总数。**

老平台进入页时会把 `testingPhaseList[0]` 作为默认阶段直接查询。  
新平台当前系统测试非法页的 scope provider 默认是空范围，进入页不会自动收敛到第一项阶段。

这会让“第一次打开页面”看到的总数和老平台不一致。

### 3. 非法类型语义从“列表”收敛成了“单值”

**影响范围：高。影响表格展示、筛选和导出。**

老平台 `illegalList` 允许同一条议题同时命中多个非法类型，例如“未设定严重程度 + 未设定模块”。页面和导出都能直接看到组合结果，按任一非法类型筛选时也会命中这条议题。

新平台当前事实层只保留单个 `illegalReason`，`IssueClassificationRules.illegalReason()` 会按优先级返回第一个命中原因。结果是：

1. 组合非法类型会被压成单值。
2. 按某个非法类型筛选时，可能漏掉老平台会命中的记录。
3. 表格里展示的非法类型字符串可能和老平台 `illegal_list` 不一致。

### 4. 详情字段缺少 `功能名`

**影响范围：中。影响与老平台明细核对。**

老平台展开详情里有 `功能名`。  
新平台当前 `SystemTestIllegalRecordRowResponse` 和页面详情抽屉都没有这个字段。

### 5. 单条刷新功能缺失

**影响范围：中。影响老平台同款操作可达性。**

老平台每行提供“更新本条数据并刷新页面”的按钮。  
新平台当前只有顶部“刷新最新数据”，没有单条记录刷新入口。

### 6. 模块展示方式不完全一致

**影响范围：低到中。影响用户肉眼核对。**

老平台主表和详情都以单字符串 `moduleName` 展示。  
新平台当前按 `moduleNames` 列表展示，页面上是拆分后的多标签/分隔展示。

如果一条议题有多个模块，展示形态会和老平台不一致。

### 7. 事实层里存在老平台页面不显示的额外非法语义

**影响范围：待观察。**

新平台 `IssueClassificationRules.illegalReason()` 里还存在 `流程越位` 这类事实层非法语义。当前系统测试非法页会把它们过滤掉，不直接展示。  
这项目前不作为页面功能缺口，但需要持续关注，避免后续统计口径混入非老平台范围。

## 当前结论

本轮仅完成代码对比和差异记录，未修改业务代码。  
优先级最高的待对齐项是：

1. 固定系统测试非法页的默认项目范围。
2. 对齐默认测试阶段的首项自动查询行为。
3. 处理多非法类型的保留和筛选语义。
4. 补回 `功能名` 与单条刷新能力。
