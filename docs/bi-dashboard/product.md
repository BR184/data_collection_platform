# BI 看板产品与页面规则

## 目标与边界

- BI 看板是数据采集平台一级模块，与质量看板、评审数据、代码走查、系统测试、客户问题和系统设置并列。
- 一级导航固定为“需求 -> 设计 -> 编码 -> 单元测试 -> 集成测试 -> 系统测试”；一个阶段对应一个独立页面。
- 产品版本是六页唯一的全局范围；测试轮次、模块、功能、仓库、来源和日/周粒度只在所属页面内生效。
- 首期是 PC 浏览器中的只读研发质量分析，不建设营销首页、手机/平板适配、编辑、审批、回写、轮播或自动赶工判定。
- 页面、图表、表格和下载必须共享当前筛选范围与同一来源版本；不可计算、真实空数据、未接入和来源失败分别表达，不用 `0`、旧缓存或 mock 混同。
- 需求、设计、编码和系统测试使用平台自有数据；单元测试和集成测试执行事实只来自 CAT。
- 系统测试只展示平台 `issue_fact` 的缺陷事实和修复口径，不存在执行用例数、通过用例数或系统测试通过率，也不访问 CAT。
- 六个页面的数据来源彼此独立，不做跨阶段同批次拼接；顶部产品版本只统一业务范围，不承诺各来源在同一时刻采集。

## 用户与体验

- 主要用户是产品、研发、质量和项目管理负责人，在项目复盘、质量检查和阶段分析中高频扫描、比较、下钻和下载。
- 访问后直接进入具体阶段页面；六阶段导航始终可见，仅高亮当前阶段。
- 页面首屏优先呈现核心判断，同时露出后续分析内容；信息密度适合反复工作，不使用营销式大卡片或装饰性版块。
- 支持产品版本切换、图例显隐、tooltip、表格排序和页面内筛选；编码页额外支持日/周、CC/DGM 来源和仓库筛选。
- 单元测试、集成测试允许从模块达标情况进入该模块的功能达标情况；首期不提供任意原始缺陷自由浏览。
- BI 权限只分为“查看”和“下载”：查看覆盖六个页面，下载在查看权限基础上开放所有图表下载入口。
- 下载行为与已确认静态页面一致：每张可下载图表导出当前筛选、排序和完整图表数据对应的 PNG；首期不提供整页 `.xlsx`、图表数据表或整页长截图下载。
- 平台或 CAT 发布同一产品版本的新来源数据时，已打开页面保持当前数据不变并提示可刷新；只有用户刷新后才整体切换到新来源版本。

## 六阶段页面

| 页面 | 数据来源 | 必须展示的内容 | 页面内维度 |
|---|---|---|---|
| 需求 | `review_visible_*` 及 BI 评审计算 | 问题类别、整体和模块评审缺陷密度、评审速率、质量目标、单次评审“速率 x 缺陷密度”散点 | 模块、评审记录 |
| 设计 | `review_visible_*` 及 BI 评审计算 | 与需求页同构的设计评审分析，不做跨阶段问题总数替代 | 模块、评审记录 |
| 编码 | 代码规模类与人工走查类在兼容态统一读取 `code_review_match_mode_records`、正式态读取 `code_review_formal_records`，提交类读取 GitLab 提交事实；统一由 BI 编码计算 | 提交趋势、累计新增代码、个人贡献、模块代码增量、走查问题、人工走查质量、代码质量趋势 | 日/周、CC/DGM、仓库、模块、人员 |
| 单元测试 | CAT | 整体目标达成、模块达成、模块下功能达成 | 模块、功能 |
| 集成测试 | CAT | 与单元测试页同构的整体、模块、功能达成 | 模块、功能 |
| 系统测试 | `issue_fact`、议题测试阶段定义及 BI 系统测试计算 | 质量目标、轮次修复、严重度、模块缺陷级别、模块修复率、累计/未修复、原因大类与子类、延期、人员负荷 | 测试轮次、模块、原因、当前指派人 |

### 需求与设计

- 只统计普通评审五类中的需求说明书评审或设计说明书评审；未知类型不得按标题、候选项或“其他”桶自动归入。
- 代码走查不属于普通评审，不能进入需求/设计统计。
- 不展示“评审问题总数”独立 KPI，也不恢复跨阶段问题总数对比图。
- 模块评审质量同时展示缺陷密度、评审速率和达标状态；未配置速率目标时只展示数值，不伪造达标结论。

### 编码

- 代码规模、人员贡献、模块增量与人工走查质量、问题分布、散点和注释率在兼容态统一读取 `code_review_match_mode_records`、正式态读取 `code_review_formal_records`；提交趋势读取 GitLab 提交事实，三类数据不能互相替代。
- 提交趋势使用提交数柱状图和合并请求数折线图，共用次数轴；按日/周的提交次数分布已由该卡承载，编码页不再单列“代码提交频次时间分布”卡（2026-09-10 经用户确认下线，信息与提交趋势重叠）。
- 模块代码增量使用模块类别轴、KLOC 数值轴和横向缩放，完整显示模块名称。
- 代码走查问题分布使用环形构成图；静态代码扫描结果图已下线（2026-09-15，D-12），待 PMD-Biome 以结构化分级数据接入后重建。
- 顶部只展示一次人工走查整体缺陷密度和评审速率；页面下方不重复同一整体指标。
- 模块人工走查质量分别展示缺陷密度（个/KLOC）、评审速率（行/小时）和目标状态，不使用双 Y 轴。
- 单次人工走查散点横轴为 KLOC/小时，纵轴为个/KLOC，目标区间以辅助带或辅助线表达。
- 老平台把“代码走查缺陷密度”和“千行代码缺陷率”用于同一 KLOC 指标的不同展示维度；BI 统一命名为“代码走查缺陷密度（个/KLOC）”，在整体、模块、人员、单次走查和趋势中复用同一口径。
- 不再建立独立“编码阶段缺陷密度”或第二套“千行代码缺陷率”。代码质量趋势只保留代码注释率和代码走查缺陷密度两条独立轨道。
- 质量图表遇到少量极端值时必须保留真实数值、数据点和悬浮明细，并压缩没有观测值的显著坐标区间；不得写死轴上限或裁掉极端记录。

### 单元测试与集成测试

- 页面结构统一为整体、模块、功能三层，移除旧四项 KPI 和模块执行条。
- 顶部连续指标带展示整体通过率、目标通过率、通过数/执行数和达标状态。
- 模块和功能使用横向达标矩阵，逐行直显通过率、通过数/执行数、目标线和状态。
- 模块列表支持高基数浏览；功能使用稳定 ID 关联模块，显示真实产品功能名称，不使用“异常处理”等测试过程概念代替业务功能。
- 正式数据不得使用静态 mock、零值、评审记录或系统测试缺陷修复率补齐。
- CAT 全权提供两个页面所需数据。CAT 已有执行数、通过数或通过率等聚合值时直接消费；没有聚合值时，由 BI 使用 CAT 提供的基础数据计算，不允许数据采集平台事实参与补齐。
- 当前 CAT 手册只说明一套项目、版本/阶段、模块和功能统计协议，且只说明整体/模块/功能通过率与模块功能通过/未通过数量，没有三层执行/通过用例数；这些功能数量不能替代用例数量。单元测试和集成测试页面分别配置 CAT 阶段 ID；来源身份未补齐前保持 `INCOMPLETE`，但允许查看真实 CAT 统计。
- CAT 目录首次发布后，系统设置应优先预填唯一的默认项目、版本和 UT/IT 阶段建议，管理员只需核对并保存；建议有歧义时保持空白，保存后的稳定 ID 映射才进入同步。连接/读取超时、响应上限和快照保留数不作为页面设置。

### 系统测试

- 页面先展示一级缺陷、P1、P2 三项质量目标，再展示整体缺陷概览。一级缺陷是严重程度，P1/P2 是优先级，文案必须明确区分。
- 各轮次缺陷修复包含一级、二级、三级、提交总数、已关闭和未关闭；严重度用绝对数量堆叠主轨，关闭状态用比例次轨并直显数量，提交总数独立展示，不叠加穿越柱体的折线。
- 轮次按“议题测试阶段定义”顺序排列，只展示当前版本中实际提交过有效缺陷的轮次；目录中尚无缺陷事实的未来轮次不显示。轮次较多时默认显示最新窗口并可纵向回看全部有数据轮次。
- 严重度只使用一级、二级、三级；模块级同时展示累计发现与当前未修复，不保留整体“未修复缺陷级别”圆环。
- 缺陷原因同时展示大类饼图和子类高基数柱状图，两级共享版本和缺陷范围，未归类项保持独立。
- 申请延期使用原因 x 严重度热力矩阵；模块修复率和延期图在可读宽度下按 `7:5` 并排，不足时回落单列。
- 人员负荷按当前指派人常驻显示缺陷总数和当前待修复数，保留一级/二级/三级及已修复/待修复守恒关系；合法修复状态评论作者只表示实际修复历史归属，不能用于归属尚未修复的议题。

|---|---|---|

- 页面只选择模板、显式变体、数据适配器和布局，不直接拼接重复业务 `series`。
- 同模板共享响应式布局、tooltip、图例、缩放、标签对比色、空状态和 PNG 下载行为。
- 新图表先验证既有模板是否可表达；不得制造万能渲染器或按页面复制 ECharts option。

## 视觉规则

- 使用平台现有 Vue、Element Plus 和图标体系，保持白色、克制、低圆角、弱边框的企业分析工作台风格。
- 图表布局只使用紧凑/宽图 `4:8`、半幅 `6:6`、主辅 `7:5` 和全幅四类稳定结构；空间不足时单列回落。
- 高基数模块、功能、人员图支持搜索、排序、10/20 项可视窗口和图内滚动；PNG 下载前必须切换为完整数据布局，不能被可视窗口或图表缩放截断。
- 有色图形内部文字按实际底色在黑/白中选择高对比色；轴、图例和 tooltip 使用中性文字层级。
- 业务图表标准色板为蓝 `#3B82F6`、青绿 `#14B8A6`、绿 `#22C55E`、橙 `#FB923C`、红 `#EF4444`、石板灰 `#94A3B8`。
- 达标/已修复用绿色，告警/二级用橙色，异常/一级/未通过用红色，未归类和中性系列用石板灰。
- 模块修复率整体轨道保留旧版例外：橙 `#FA8C16`、绿 `#52C41A`、未填充 `#F0F2F5`；例外不扩散到其它图表。
- 视觉稿数值只验证布局，不构成统计结果、字段或契约。
