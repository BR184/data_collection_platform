# 集成测试平台接口手册

---

# 1. 获取所有项目信息

## 1.1 接口概述

| 项目     | 内容                                                           |
| -------- | -------------------------------------------------------------- |
| 接口名称 | 获取所有项目信息                                               |
| 接口地址 | `/integrationSearch/getAllProject`                           |
| 请求方式 | `POST`                                                       |
| 请求参数 | 无                                                             |
| 接口描述 | 查询数据库中`project` 集合的全部项目数据，按创建时间升序返回 |

## 1.2 请求说明

### 1.2.1 请求头

| Header       | 值                   | 是否必填 |
| ------------ | -------------------- | -------- |
| Content-Type | `application/json` | 否       |

### 1.2.2 请求参数

> 无。本接口不需要传递任何参数。

### 1.2.3 请求示例

```http
POST /getAllProject
```

## 1.3 响应说明

### 1.3.1 响应结构

| 属性        | 类型              | 说明                                     |
| ----------- | ----------------- | ---------------------------------------- |
| `code`    | Integer           | 状态码，`200` 表示成功，其他值表示失败 |
| `message` | String            | 提示信息                                 |
| `data`    | `List<Project>` | 项目信息列表，按创建时间升序排列         |

### 1.3.2 data 字段说明（Project 对象）

`data` 为一个 JSON 数组，数组中每个元素为一个 `Project` 对象，具体字段如下：

| 属性               | 类型              | 说明                                                          | 示例值                                     |
| ------------------ | ----------------- | ------------------------------------------------------------- | ------------------------------------------ |
| `id`             | String            | 项目唯一标识，创建时自动生成的 UUID                           | `"a1b2c3d4-e5f6-7890-abcd-ef1234567890"` |
| `name`           | String            | 项目名称                                                      | `"自动驾驶测试项目"`                     |
| `note`           | String            | 项目备注/描述信息                                             | `"用于自动驾驶场景的标准测试用例管理"`   |
| `createTime`     | String (ISO 8601) | 项目创建时间，UTC 时间格式                                    | `"2025-01-15T08:30:00Z"`                 |
| `createUserId`   | String            | 项目创建者的用户 ID                                           | `"user_001"`                             |
| `defaultProject` | Boolean           | 是否为默认项目，`true` 表示默认项目，`false` 表示普通项目 | `false`                                  |

### 1.3.3 成功响应示例

```json
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "name": "自动驾驶测试项目",
      "note": "用于自动驾驶场景的标准测试用例管理",
      "createTime": "2025-01-15T08:30:00Z",
      "createUserId": "user_001",
      "defaultProject": false
    },
    {
      "id": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
      "name": "ADAS功能测试项目",
      "note": "高级辅助驾驶系统功能测试",
      "createTime": "2025-02-20T10:15:00Z",
      "createUserId": "user_002",
      "defaultProject": true
    }
  ]
}
```

### 1.3.4 异常响应示例

```json
{
  "code": 500,
  "message": "服务器内部错误",
  "data": null
}
```

## 1.4 业务逻辑说明

| 说明项                    | 内容                                                                            |
| ------------------------- | ------------------------------------------------------------------------------- |
| **数据来源**        | MongoDB 数据库，集合名称为`project`                                           |
| **排序规则**        | 按`createTime`（创建时间）**升序**（ASC）排列，最早创建的项目排在最前面 |
| **ID 生成方式**     | 创建项目时由后端自动生成 UUID（`UUID.randomUUID().toString()`），前端无需传入 |
| **createTime 时区** | 存储为 UTC 时间（`Instant` 类型），前端展示时如需本地时间请自行转换           |
| **defaultProject**  | 新建项目时默认为`false`，仅系统预设的默认项目为 `true`                      |

## 1.5 前端使用建议

1. **项目列表渲染**：本接口返回的数据可用于渲染项目下拉选择框或项目列表页面。
2. **默认项目标识**：前端可根据 `defaultProject` 字段为默认项目添加标识标签（如"默认"徽章）。
3. **时间格式化**：`createTime` 为 UTC 时间，前端展示时建议转换为本地时间格式（如 `2025-01-15 16:30`）。
4. **接口调用时机**：建议在页面初始化时调用，用于加载项目选项列表。

# 2. 根据项目 ID 获取测试阶段树

## 2.1 接口概述

| 项目     | 内容                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------- |
| 接口名称 | 根据项目 ID 获取测试阶段树结构                                                                 |
| 接口地址 | `/testingPhase/getAllByProjectId`                                                            |
| 请求方式 | `POST`                                                                                       |
| 请求参数 | `projectId`（可选）                                                                          |
| 接口描述 | 根据项目 ID 查询该项目下所有版本及其对应的测试阶段数据，返回用于前端树形组件展示的层级数据结构 |

## 2.2 请求说明

### 2.2.1 请求头

| Header       | 值                   | 是否必填 |
| ------------ | -------------------- | -------- |
| Content-Type | `application/json` | 否       |

### 2.2.2 请求参数

| 参数名        | 类型   | 是否必填 | 说明                                                                                                                                                  |
| ------------- | ------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `projectId` | String | 否       | 项目 ID。若不传或为空，后端会自动获取系统默认项目 ID；若默认项目也不存在，则返回`null`。建议前端默认不传，由后端兜底处理，也可显式传入指定项目 ID。 |

### 2.2.3 请求示例

**示例一：不传 projectId（使用默认项目）**

```http
POST /getAllByProjectId
```

**示例二：指定 projectId**

```http
POST /getAllByProjectId?projectId=a1b2c3d4-e5f6-7890-abcd-ef1234567890
```

## 2.3 响应说明

### 2.3.1 响应结构

| 属性        | 类型                      | 说明                                       |
| ----------- | ------------------------- | ------------------------------------------ |
| `code`    | Integer                   | 状态码，`200` 表示成功，其他值表示失败   |
| `message` | String                    | 提示信息                                   |
| `data`    | `List<TestingPhaseDTO>` | 测试阶段树结构数据，按版本维度组织的多级树 |

### 2.3.2 返回数据层级关系

返回的 `data` 是一个 **树形结构** 的 JSON 数组，整体层级关系如下：

```
data (List)
 └── 顶级节点：项目版本（ProjectVersion）
      ├── 基本信息：版本ID、版本名称、创建时间
      ├── 标识字段：curVersion（是否当前版本）、defaultProject（是否默认项目）、disabled（是否禁用选择）
      └── children (List)
           └── 子节点：测试阶段（TestingPhase）
                ├── 基本信息：阶段ID、阶段名称、创建时间、备注、结束时间
                └── 关联字段：projectId、versionId、group_id（父级绑定）
```

### 2.3.3 TestingPhaseDTO 字段说明

> ⚠️ 顶级节点（版本）与子节点（测试阶段）部分字段含义有所不同，下表已分别标注。

| 属性               | 类型    | 顶级节点（版本）含义                              | 子节点（测试阶段）含义                   | 示例值                                 |
| ------------------ | ------- | ------------------------------------------------- | ---------------------------------------- | -------------------------------------- |
| `id`             | String  | 版本 ID（`versionId`）                          | 测试阶段记录 ID                          | `"v001"` 或 `"tp-abc123"`          |
| `name`           | String  | 版本名称                                          | 测试阶段名称（`phaseName`）            | `"V1.0.0"` 或 `"SIT测试阶段"`      |
| `createTime`     | String  | 版本创建时间（字符串格式）                        | 测试阶段创建时间（字符串格式）           | `"2025-01-15T08:30:00Z"`             |
| `children`       | List    | 该版本下的测试阶段列表，无数据时为`null`        | 子级测试阶段列表（如有），通常为`null` | `[...]` 或 `null`                  |
| `note`           | String  | 固定为`null`                                    | 测试阶段备注信息                         | `"系统集成测试"` 或 `null`         |
| `group_id`       | String  | 固定为`"0"`（表示顶级节点，无父级）             | 用于绑定父级节点 ID                      | `"0"` 或 `"v001"`                  |
| `endTime`        | Date    | 固定为`null`                                    | 测试阶段结束时间                         | `"2025-03-01T00:00:00Z"` 或 `null` |
| `curVersion`     | Boolean | `true` 表示该版本为当前版本，否则不设置         | 子节点通常不设置此字段                   | `true` 或 `null`                   |
| `projectId`      | String  | 顶级节点不设置（`null`）                        | 所属项目 ID                              | `"a1b2c3d4-..."` 或 `null`         |
| `versionId`      | String  | 顶级节点不设置（`null`）                        | 所属版本 ID                              | `"v001"` 或 `null`                 |
| `disabled`       | Boolean | 固定为`true`（顶级版本节点不可被选择）          | 子节点通常不设置（默认可选择）           | `true` 或 `null`                   |
| `defaultProject` | Boolean | `true` 表示该项目为系统默认项目，`false` 否则 | 子节点通常不设置此字段                   | `true` / `false` / `null`        |

## 2.4 业务逻辑说明

| 说明项                            | 内容                                                                                                                                                     |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **projectId 兜底机制**      | 若请求未传`projectId`，后端自动获取系统默认项目 ID；若默认项目不存在，则返回 `null`。建议前端首次加载时不传该参数，由后端兜底返回默认项目的数据。    |
| **树形结构组成**            | 顶级节点为**项目版本**（`ProjectVersion`），每个版本节点下挂载该版本对应的**测试阶段**（`TestingPhase`）作为子节点（`children`）。     |
| **disabled 字段用途**       | 顶级版本节点的`disabled` 固定为 `true`，表示版本节点本身不可被前端选择器选中，仅作为分组容器；子级测试阶段节点默认可选。                             |
| **curVersion 字段用途**     | 标识当前生效的版本，前端可据此高亮显示或默认展开。                                                                                                       |
| **defaultProject 字段用途** | 标识当前查询的项目是否为系统默认项目，前端可据此显示默认标记。                                                                                           |
| **group_id 字段用途**       | 顶级节点为`"0"`，子节点为父级版本 ID，用于前端构建父子层级关系。                                                                                       |
| **排序规则**                | 版本列表顺序取决于`projectVersionService.getProjectVersionByProjectId` 的内部实现，测试阶段顺序取决于 `testingPhaseDao.findByVersionId` 的返回顺序。 |

## 2.5 前端使用建议

1. **树形组件渲染**：使用 Element UI 的 `el-tree` 或 `el-cascader` 等组件，配置 `children` 字段作为子节点。
2. **禁用选择版本节点**：通过 `disabled: true` 属性，版本级别节点不可选中，仅测试阶段叶子节点可被选择。
3. **默认展开当前版本**：根据 `curVersion: true` 标识，默认展开当前版本节点及其子节点。
4. **首次加载**：建议首次调用时不传 `projectId`，由后端返回默认项目数据，后续切换项目时再显式传入。

# 3. 查询集成测试统计数据

## 3.1 接口概述

| 项目     | 内容                                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 接口名称 | 根据测试阶段 ID 查询集成测试统计数据                                                                                           |
| 接口地址 | `/integrationSearch/getStatisticsInfoByTPId`                                                                                 |
| 请求方式 | `POST`                                                                                                                       |
| 请求参数 | `testingPhaseId`（必填）                                                                                                     |
| 接口描述 | 根据测试阶段 ID，查询该阶段下所有模块及功能的集成测试统计数据，包括功能通过/未通过数量、整体通过率等，用于集成测试统计看板展示 |

## 3.2 请求说明

### 3.2.1 请求头

| Header       | 值                   | 是否必填 |
| ------------ | -------------------- | -------- |
| Content-Type | `application/json` | 否       |

### 3.2.2 请求参数

| 参数名             | 类型   | 是否必填     | 说明                                                                 |
| ------------------ | ------ | ------------ | -------------------------------------------------------------------- |
| `testingPhaseId` | String | **是** | 测试阶段 ID，通过`/getAllByProjectId` 接口返回的子节点 `id` 获取 |

### 3.2.3 请求示例

```http
POST /getStatisticsInfoByTPId?testingPhaseId=tp-aaa-111
```

## 3.3 响应说明

### 3.3.1 响应结构

| 属性        | 类型                    | 说明                                                        |
| ----------- | ----------------------- | ----------------------------------------------------------- |
| `code`    | Integer                 | 状态码，`200` 表示成功，其他值表示失败                    |
| `message` | String                  | 提示信息                                                    |
| `data`    | `Map<String, Object>` | 包含`result`（模块统计列表）和 `passRate`（整体通过率） |

### 3.3.2 data 字段说明

`data` 是一个 Map 对象，包含以下两个键：

| 键名         | 类型                     | 说明                                     |
| ------------ | ------------------------ | ---------------------------------------- |
| `result`   | `List<StatisticsInfo>` | 顶级模块的统计数据列表                   |
| `passRate` | Double                   | 整体测试通过率（百分比数值，如`85.5`） |

### 3.3.3 返回数据层级关系

```
data (Map)
 ├── result (List<StatisticsInfo>)  ── 顶级模块统计列表
 │    ├── 模块 A 统计
 │    │    ├── id: 模块ID
 │    │    ├── moduleName / name: 模块名称
 │    │    ├── passFeatureCount: 通过功能数
 │    │    ├── notPassFeatureCount: 未通过功能数
 │    │    └── testPassRate: 模块通过率
 │    ├── 模块 B 统计
 │    └── ...
 │
 └── passRate (Double)  ── 整体通过率（所有模块汇总）
```

### 3.3.4 StatisticsInfo 字段说明（模块级统计）

`result` 数组中每个元素代表一个**顶级模块**的统计信息：

| 属性                    | 类型    | 说明                                                               | 示例值           |
| ----------------------- | ------- | ------------------------------------------------------------------ | ---------------- |
| `id`                  | String  | 顶级模块 ID                                                        | `"module-001"` |
| `moduleName`          | String  | 模块名称                                                           | `"草图模块"`   |
| `name`                | String  | 模块名称（与`moduleName` 相同）                                  | `"草图模块"`   |
| `passFeatureCount`    | Integer | 该模块下测试**通过**的功能数量（功能通过率 ≥ 95% 视为通过） | `12`           |
| `notPassFeatureCount` | Integer | 该模块下测试**未通过**的功能数量                             | `3`            |
| `testPassRate`        | Double  | 该模块的整体测试通过率（百分比）                                   | `80.0`         |
| `featureUniqueId`     | String  | 模块级统计时通常为`null`，功能级统计时为功能唯一标识             | `null`         |

> ⚠️ **通过率判定规则**：当前硬编码为 **95%**，即功能的集成测试通过率达到 95% 及以上才视为"通过"。代码中已标注 `TODO`，后期将改为可自定义配置。

## 3.4 业务逻辑说明

| 说明项                           | 内容                                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **数据查询入口**           | 通过`testingPhaseId` 获取测试阶段信息，再从中提取 `projectId` 和 `versionId`，锁定统计范围      |
| **模块层级结构**           | 从项目下所有模块中筛选出顶级模块（`parentModuleUniqueId` 为顶级标识），以顶级模块为维度进行统计汇总 |
| **功能通过率判定**         | 单个功能的通过率达到**≥ 95%** 视为"通过"，否则视为"未通过"。该阈值目前硬编码，后期将改为可配置 |
| **通过功能数计算**         | `passFeatureCount` = 该模块下通过率 ≥ 95% 的功能数量                                               |
| **未通过功能数计算**       | `notPassFeatureCount` = 已派发功能总数 - 通过功能数                                                 |
| **已派发功能过滤**         | 仅统计已派发用例数量 > 0 且派发用例状态为"在用"的功能，派发数量为 0 或全部弃用的功能不计入统计        |
| **整体通过率（passRate）** | 基于所有模块的统计数据汇总计算得出                                                                    |
| **排序规则**               | 模块级统计列表按原始模块顺序返回；功能级统计（内部调用）按通过率降序排列                              |
| **用例状态过滤**           | 统计过程中仅拉取"在用"状态的测试用例，"弃用"状态的用例不纳入统计                                      |
| **引用用例去重**           | 对引用关系进行去重处理，避免同一引用被多次统计                                                        |

## 3.5 前端使用建议

1. **数据展示**：`result` 列表可用于渲染模块维度的统计表格或图表（如柱状图、进度条）。
2. **通过率展示**：`passRate` 可用于页面顶部的整体通过率仪表盘或大数字展示。
3. **通过/未通过对比**：每个模块的 `passFeatureCount` 和 `notPassFeatureCount` 可用于双柱对比图或饼图展示。
4. **颜色标识建议**：
   - 通过率 ≥ 95%：绿色
   - 通过率 80% ~ 95%：黄色
   - 通过率 < 80%：红色
5. **接口调用时机**：建议在用户从测试阶段树中选择某个测试阶段节点后调用此接口，展示该阶段的统计概览。

# 4. 模块下钻获取功能级统计数据

## 4.1 接口概述

| 项目     | 内容                                                                                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 接口名称 | 根据模块 ID 下钻获取功能级测试统计数据                                                                                                                      |
| 接口地址 | `/getFeatureInfoByModuleId`                                                                                                                               |
| 请求方式 | `POST`                                                                                                                                                    |
| 请求参数 | `FeatureInfoQueryDTO`（JSON Body）                                                                                                                        |
| 接口描述 | 根据模块 ID 和测试阶段 ID，下钻查询该模块下所有功能的集成测试详细统计数据，支持分页和自定义排序。用于统计看板中点击某个模块后展示其下级功能的明细统计信息。 |

## 4.2 请求说明

### 4.2.1 请求头

| Header       | 值                   | 是否必填     |
| ------------ | -------------------- | ------------ |
| Content-Type | `application/json` | **是** |

> ⚠️ 本接口使用 `@RequestBody` 接收参数，必须以 JSON 格式发送请求体，`Content-Type` 必须设置为 `application/json`。

### 4.2.2 请求参数（FeatureInfoQueryDTO）

| 参数名             | 类型    | 是否必填     | 说明                                                                                                |
| ------------------ | ------- | ------------ | --------------------------------------------------------------------------------------------------- |
| `moduleId`       | String  | **是** | 模块 ID（顶级模块 ID），通过`/getStatisticsInfoByTPId` 接口返回的 `result` 列表中的 `id` 获取 |
| `testingPhaseId` | String  | **是** | 测试阶段 ID，通过`/getAllByProjectId` 接口返回的子节点 `id` 获取                                |
| `page`           | Integer | 否           | 当前页码，从 1 开始。不传则不分页，返回全量数据                                                     |
| `pageSize`       | Integer | 否           | 每页条数。不传则不分页，返回全量数据                                                                |
| `sortField`      | String  | 否           | 排序字段。传`null` 或不传时默认按通过率降序排列                                                   |
| `sortOrder`      | String  | 否           | 排序顺序，`"desc"` 表示降序，`"asc"` 表示升序。不传时默认降序                                   |

### 4.2.3 请求示例

**示例一：基础下钻查询（不分页、默认排序）**

```http

  "sortOrder": "desc"
}
```

## 4.3 响应说明

### 4.3.1 响应结构

| 属性        | 类型                                   | 说明                                     |
| ----------- | -------------------------------------- | ---------------------------------------- |
| `code`    | Integer                                | 状态码，`200` 表示成功，其他值表示失败 |
| `message` | String                                 | 提示信息                                 |
| `data`    | `StatisticsInfoPage<StatisticsInfo>` | 分页包装的功能级统计数据对象             |

### 4.3.2 StatisticsInfoPage 字段说明

`data` 为一个分页包装对象，具体字段如下：

| 属性                   | 类型                     | 说明                         |
| ---------------------- | ------------------------ | ---------------------------- |
| `statisticsInfoList` | `List<StatisticsInfo>` | 当前页的功能级统计数据列表   |
| `page`               | Integer                  | 当前页码，不分页时为`null` |
| `pageSize`           | Integer                  | 每页条数，不分页时为`null` |
| `totalCount`         | Long                     | 符合条件的总记录数           |
| `sumPageCount`       | Integer                  | 总页数，不分页时为`null`   |

### 4.3.3 StatisticsInfo 字段说明（功能级统计）

`statisticsInfoList` 数组中每个元素代表一个**功能节点**的统计信息：

| 属性                    | 类型    | 说明                                                                   | 示例值            |
| ----------------------- | ------- | ---------------------------------------------------------------------- | ----------------- |
| `id`                  | String  | 功能唯一标识（当该展示节点仅包含一个功能时为此值，多个功能时可能为空） | `"feature-001"` |
| `name`                | String  | 功能/展示节点名称                                                      | `"草图绘制"`    |
| `featureUniqueId`     | String  | 功能唯一标识                                                           | `"feature-001"` |
| `featureLabel`        | String  | 功能标签信息                                                           | `"核心功能"`    |
| `testPassRate`        | Double  | 该功能的测试通过率（百分比）                                           | `92.5`          |
| `passFeatureCount`    | Integer | 功能级统计时通常不设置此字段                                           | `null`          |
| `notPassFeatureCount` | Integer | 功能级统计时通常不设置此字段                                           | `null`          |

> ⚠️ **展示节点与功能的关系**：由于文件夹层级结构变动，一个展示节点可能包含多个功能（`featureUniqueId`）。当展示节点仅包含一个功能时，`id` 字段直接赋值为该功能的 `uniqueId`；包含多个功能时，`id` 可能为空。

## 4.4 业务逻辑说明

| 说明项                             | 内容                                                                                                                                                                                            |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **下钻统计粒度**             | 下钻统计只细化到**最上层**的 `lastModule = true` 模块层的下一层（即功能层），不再继续往下递归。这是与原有统计逻辑的重要区别                                                             |
| **层级结构变动说明**         | 由于文件夹解析规则变动，一个`lastModule = true` 的模块下可能仍包含 `lastModule = true` 的子模块，功能在最底层。本接口在查找时从上到下定位最上层的 `lastModule` 层，取其下一层作为展示粒度 |
| **展示节点与功能关系**       | 一个展示节点可能包含多个功能（`featureUniqueId`），统计数据为这些功能的汇总值                                                                                                                 |
| **功能标签（featureLabel）** | 通过功能的唯一标识和项目 ID 获取对应的功能标签数据，用于前端展示                                                                                                                                |
| **排序规则**                 | 默认按通过率降序排列；若传入`sortField` 和 `sortOrder`，则按指定字段和顺序排序                                                                                                              |
| **分页规则**                 | 若传入`page` 和 `pageSize`，则对排序后的列表进行分页截取；不传则返回全量数据                                                                                                                |
| **用例状态过滤**             | 统计过程中仅拉取"在用"状态的测试用例，"弃用"状态的用例不纳入统计                                                                                                                                |
| **引用用例去重**             | 对引用关系进行去重处理，避免同一引用被多次统计                                                                                                                                                  |
| **已派发功能过滤**           | 仅统计已派发用例数量 > 0 且派发用例状态为"在用"的功能                                                                                                                                           |

## 4.5 前端使用建议

1. **触发时机**：用户在统计看板（`/getStatisticsInfoByTPId` 返回的模块列表）中点击某个模块时，调用本接口下钻展示该模块下的功能明细。
2. **分页处理**：当模块下功能数量较多时，建议传入 `page` 和 `pageSize` 进行分页查询，配合前端分页组件使用。
3. **排序交互**：
   - 默认按通过率降序，前端可在表头提供排序切换按钮
   - 用户点击表头时，传入对应的 `sortField` 和 `sortOrder` 重新请求
4. **颜色标识建议**：
   - 通过率 ≥ 95%：绿色
   - 通过率 80% ~ 95%：黄色
   - 通过率 < 80%：红色
5. **功能标签展示**：`featureLabel` 字段可用于在功能名称旁展示标签徽章（如"核心功能"、"基础功能"）。
