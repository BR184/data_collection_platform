# 标签组筛选与默认模块范围方案

日期：2026-06-22

## 1. 背景

系统测试缺陷汇总等统计页面当前存在两个容易混淆的问题：

1. 条件筛选里的 `模块名称 = 值` 是文本输入框，用户无法像评审数据管理页面一样在“值”控件里选择已维护的标签组。
2. 新平台事实层展示出了比老平台更多的模块标签。老平台默认只展示一批收口后的模块，新平台如果直接展示全量模块，会让用户感觉与老平台不一致。

这两个问题不能通过硬编码模块名单或按页面临时补丁解决。定版方案如下。

## 2. 标签组使用边界

标签组是按值类型组织的可复用值集合，不是字段集合，也不是字符串输入框的替代品。

1. 只要字段值类型匹配，字段就可以使用同值类型标签组。
2. `STRING` 表示字段值类型是字符串，不表示页面必须渲染成普通文本输入框。
3. `模块`、`模块名称`、`模块名`、`moduleName`、`moduleNames` 在业务上属于同一个模块维度。
4. 字符串标签组可以应用到模块字段、人员字段、状态字段等任意已声明支持标签组的字符串字段。
5. 标签组仍然只能出现在现有条件筛选的“值”控件中，不新增独立标签组筛选区，不新增 `labelGroupFilters` 请求参数。
6. 文本型字段如果声明支持标签组，值控件必须同时支持：
   - 选择同值类型标签组。
   - 输入普通文本值。
   普通文本值只用于当前页面的一次性筛选，不会被保存为标签组成员；标签组成员必须从平台登记候选来源中选择，不能凭空输入创造。
7. 标签组条件提交后，后端必须展开为成员值再参与查询、统计、下钻、导出和规则说明。不能只在前端显示可选标签组而后端忽略。

## 3. 默认模块范围方案

新平台事实层保留完整模块数据；页面默认体验通过用户可维护的标签组进行收口。

1. 事实层不删除、不屏蔽、不覆盖额外模块标签。
2. 系统测试统计页默认可应用一个“模块范围标签组”，用于让页面默认展示接近老平台的模块范围。
3. 这个默认范围本质是标签组筛选条件，例如：
   - `模块 包含任意一个 <默认模块范围标签组>`
4. 默认模块范围不能写死在代码里。
5. 默认模块范围的成员不能写死在代码里。
6. 用户或管理员必须可以维护这个标签组成员：
   - 想继续保持老平台体验，就保留老平台模块集合。
   - 想查看更多模块，就把这些模块加入默认模块范围标签组。
   - 想临时排除某些模块，可以通过普通条件筛选或调整标签组完成。
7. 系统默认标签组直接放在普通标签组列表中维护，不再单独展示“默认应用”表格。
8. 系统默认标签组的名称代表作用页面，例如 `系统测试缺陷汇总`；列表中只额外显示“系统默认”标识。
9. 默认标签组筛选代表老平台写死模块收口规则的数据化版本，只要该系统默认标签组启用且有效，就与用户显式设置的同字段筛选条件同时生效。
10. 用户显式设置模块条件或另一个模块标签组时，语义是在默认模块范围基础上继续收窄；如需放出更多模块，应编辑默认模块范围标签组成员或停用这个系统默认标签组。
11. 默认筛选必须进入同一套 `filterGroup` 语义，保证页面、下钻、导出、规则说明和接口调用口径一致。
12. 如果系统默认标签组不存在、未启用或成员为空，不得把页面筛成空白；应退化为不应用默认模块范围，并在管理侧可排查。
13. 系统默认标签组由迁移预置为空的字符串静态组，用户不需要手工创建；后续只维护成员、启用状态和备注。
14. 第一批预置名单排除质量看板、其他看板、议题多元看板、代码走查多元看板、系统测试议题查询和系统设置页。预置名称为：`评审数据管理`、`代码走查非法数据`、`系统测试缺陷汇总`、`申请延期缺陷分析`、`系统测试非法数据`、`系统测试缺陷原因分析`、`议题阶段统计`、`客户问题缺陷汇总`、`客户问题缺陷非法数据`、`客户问题缺陷原因分析`、`CC_PRODUCT议题`、`延期问题`、`缺陷响应效率`、`按功能展示缺陷数量`。存在同名页面时使用模块前缀避免标签组全局唯一名称冲突。

## 4. 建议实现落点

### 4.1 字段元数据

统计板后端字段定义需要返回：

- `labelGroupEnabled`
- `labelGroupValueType`

`moduleName` 等模块字段应声明为 `labelGroupEnabled=true`、`labelGroupValueType=STRING`。

### 4.2 前端条件筛选

`StatisticFilterBuilder` 不能只在 `select` 字段上展示标签组。

支持标签组的文本字段也应使用可搜索值控件，让用户既能选择标签组，也能继续输入普通文本做一次性筛选。注意：这里的普通文本输入只属于页面筛选条件，不等于标签组成员维护；标签组设置页不得允许用户输入候选来源外成员。

### 4.3 后端标签组展开

统计板收到 `valueType=LABEL_GROUP` 的条件后，应统一调用标签组展开服务，得到成员值后再匹配。

展开后仍使用现有集合关系：

- `intersects`
- `notIntersects`
- `containsAll`
- `notContainsAll`

### 4.4 系统默认标签组

系统默认标签组不需要单独的用户配置表格。页面默认应用关系由服务端按受控规则识别：

- 标签组名称：例如 `系统测试缺陷汇总`。
- 页面或统计板 key：例如 `system-test-defect-summary`。
- 字段 key：例如 `moduleName`。
- 默认操作符：例如 `intersects`。

用户只在普通标签组表里维护这条标签组的成员、启用状态和备注。

### 4.5 管理入口

标签组设置页不展示单独的“默认应用”区域。普通标签组表中通过“系统默认”标识提示哪些标签组会被页面默认套用。

## 5. 验收要点

1. 系统测试缺陷汇总的“模块名称/模块”条件值控件可以选择用户维护的字符串标签组。
2. 同一个字符串标签组可以同时用于评审数据管理的模块字段和系统测试缺陷汇总的模块字段。
3. 文本型字段支持标签组后，仍可输入普通文本值做一次性筛选；但标签组成员维护只能从候选来源选择。
4. 默认模块范围不是代码常量，也没有硬编码模块成员。
5. 修改默认模块范围标签组成员后，重新查询页面即可看到默认展示范围变化。
6. 用户显式设置模块筛选条件时，仍与默认模块范围同时生效，最终结果是默认范围与用户条件的交集。
7. 用户要扩大默认可见模块范围时，通过编辑系统默认标签组成员或停用这条系统默认标签组完成。
8. 页面、下钻、导出、规则说明使用同一默认筛选口径。

## 6. 后续项：客户问题测试阶段切换

客户问题模块下，除 `CC_PRODUCT` 议题页外，后续也需要支持类似系统测试的“测试阶段”切换能力，例如 `CC2026R3`、`CC2026R4` 这种父级阶段。

这项需求只记录为后续范围，不混入本次标签组默认模块范围实现。后续实现前必须先确认：

1. 客户问题各页面的阶段来源是里程碑、测试阶段定义表，还是另一张老平台配置表。
2. `CC_PRODUCT` 议题页为什么不需要阶段切换，其他客户问题页面各自使用哪一个事实字段。
3. 切换测试阶段后，页面、下钻、导出和规则说明是否需要统一沿用同一筛选口径。
