# 议题测试阶段定义两级维护方案

日期：2026-06-22

## 1. 固定结论

1. “议题测试阶段定义”属于系统级配置，入口固定为“系统设置 - 议题测试阶段定义”，不放在“系统测试”业务模块下。
2. 页面按两级维护：
   - 父级阶段名称：例如 `CC2026R3`、`CC2026R4`、`CC2026R2`。
   - 子级测试阶段名称：例如 `CC2026R3第一轮系统测试`、`CC2026R3第二轮系统测试`、`CC2026R3回归测试`。
3. 父级阶段和子级测试阶段都必须支持新增、编辑、删除、启停和排序。
4. 父级阶段排序就是系统测试及客户问题相关页面“测试阶段 / 切换里程碑”下拉的展示顺序。
5. 业务页面的父级下拉只展示启用父级阶段；选择父级后，后端按表展开该父级下启用的子级测试阶段，再匹配事实层 `testing_phase`。
6. 子级测试阶段排序就是后端展开和管理页显示该父级轮次的顺序。

## 2. 数据来源和字段语义

测试阶段定义以老平台 `testing_phase` 表导出数据为准。新平台保留老平台字段语义，但把父子层级显式数据化：

| 老平台字段 | 新平台语义 |
| --- | --- |
| `项目代号` | 父级阶段名称，维护在 `testing_phase_groups.name`，并同步到子级 `testing_phase_calendar.legacy_phase_name` |
| `任务名称（简体中文）` | 子级测试阶段名称，维护在 `testing_phase_calendar.testing_phase` |
| `优先级/序号` | 初始父级排序，维护在 `testing_phase_groups.sort_order`，并保留到 `testing_phase_calendar.legacy_sort_order` |
| `状态/标志` | 启停状态；父级和子级都可维护 |
| `原始数据ID` | 老平台原始 ID，保留在 `testing_phase_calendar.legacy_source_id` |

## 3. 页面行为

1. 左侧维护父级阶段名称，点击某个父级后，右侧只显示该父级下的子级测试阶段名称。
2. 父级停用后，不进入业务页面的测试阶段 / 里程碑下拉；其子级也不会参与父级展开匹配。
3. 子级停用后，父级仍可进入下拉，但展开匹配时不包含该子级。
4. 删除父级会删除其下子级测试阶段定义；这是配置删除，不删除事实数据。
5. 新增子级时必须归属到一个父级阶段；不允许产生没有父级阶段的测试阶段定义。

## 4. 统计页使用规则

1. 系统测试缺陷汇总、申请延期缺陷分析、缺陷原因分析、议题阶段统计等页面的父级下拉来自启用的父级阶段定义。
2. 这些页面不能再从 `issue_fact.testing_phase`、GitLab 标签字符串或子级测试阶段名称反推父级下拉。
3. 系统测试缺陷汇总这类需要具体轮次匹配的页面，必须调用共享阶段目录服务，将父级阶段展开为启用的子级测试阶段集合后再查询。
4. 后续客户问题模块除 `CC_PRODUCT议题` 外的页面补测试阶段切换时，也使用同一父级阶段定义和排序规则。
