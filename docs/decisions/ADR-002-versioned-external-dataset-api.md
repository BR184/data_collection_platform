# ADR-002：版本化外部数据集 API

## Status

Accepted

## Date

2026-07-20

## Context

数据采集平台可能需要向平台进程之外的受控服务提供只读事实或统计数据。页面接口依赖 LDAP Session、CSRF、页面权限和页面 DTO，不适合作为稳定的服务间契约。外部调用需要独立认证、数据集白名单、版本治理、错误协议和令牌轮换，并且不能向平台回写数据。

## Decision

- `/api/external/v1/datasets` 只服务经过确认的进程外消费者，采用 Provider 注册、数据集白名单和独立无状态 Bearer 认证链。
- 外部接口默认关闭；每个消费者使用独立令牌摘要和最小数据集权限，生产调用限于 HTTPS 或受控内网链路。
- Provider 复用平台事实和统计服务，但不复用页面 DTO，也不接受写操作。
- 新增或扩展 Provider 前必须记录真实消费者、数据责任、schema、权限、发布和移除条件；不能因为内部页面需要数据而创建外部 Provider。
- 通用框架及其它数据集是否保留由真实消费者证据决定；未经审计不扩大，也不整体删除。

## Alternatives Considered

### 直接复用页面 API

拒绝。页面 Session、CSRF、权限和 DTO 会随界面演进，不能承担服务间契约。

### 每个消费者单独实现认证和响应协议

拒绝。会重复安全、错误和版本治理，并使数据权限无法集中审计。

### 匿名公开 JSON

拒绝。内部研发质量数据必须受控访问。

## Consequences

- 真正的外部消费者可共享受控认证、目录和版本协议。
- 内部模块不能借用该入口绕过平台 Session、RBAC 或应用服务边界。
- 外部 API 的运维和测试成本只在存在真实消费者时承担；默认关闭不等于可以保留无人使用的专用 Provider。

## 维护边界

- 本 ADR 只维护通用外部服务边界，不登记内部页面、页面下载或内部模块 DTO。
