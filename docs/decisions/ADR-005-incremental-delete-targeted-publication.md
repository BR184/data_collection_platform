# ADR-005：增量物理删除探测与精准派生发布

## 状态

已接受，2026-07-31 起实施。最终批大小、worker 数和性能硬阈值须由内网固定负载基准补充，不能由本地样本推定。

## 背景

GitLab 物理删除关系行时不会留下可由 `updated_at` 增量扫描读取的记录。现有镜像因此可能保留 active 旧关系，事实、统计、下钻、导出和记录页继续读取旧状态。全量补偿能够修正数据，但耗时为分钟级，不能承担日常实时性。

现有实现还存在三类放大或一致性缺口：删除对账每页创建持久续页任务；权威关系按每个父对象创建任务；事实影响在镜像运行结束后从可变 ODS 和 `mirror_task_id` 反查，且超过 200 个目标会回退为时间增量或全量。快照发布又按事实类型全扇出并使用全局事实任务版本，单对象变化会失效无关投影。

## 决策

正常同步只保留一条派生链：时间增量或精确信号写入 -> 批量权威范围收敛 -> 本次所选镜像表主键存在性探测 -> 事务内登记版本化根目标并写 ODS -> 有界根 ID 事实替换 -> 新旧稳定范围投影发布。

### 唯一目录

- `GitlabSourceLineageCatalog` 是推荐来源表、主键、权威关系、事实影响和无派生消费者声明的唯一事实源。
- `GitlabFactDependencyCatalog` 是事实类型到必需源表及变更信号的唯一事实源。
- 工作区依赖目录是工作区到事实类型、扫描依赖和稳定投影选择的唯一事实源。页面服务不维护表名副本。
- 新推荐表或事实 SQL 依赖必须显式登记；不存在默认忽略分支。

### 阶段与删除探测

- 镜像运行采用带持久状态的 `SCAN/AUTHORITATIVE -> RECONCILE` 屏障。只有所有生产者和权威范围成功，才可幂等规划删除探测。
- 每张表只有一个可恢复的 `RECONCILE` 任务。任务在同一行推进 keyset cursor，分页提交后可以重新排队或让行，不为每页创建新任务。
- 删除探测只分页读取镜像 active 主键，再使用真实类型、参数化批量查询验证这些键是否仍存在于 GitLab。来源查询失败必须使整页失败，不能解释为来源为空。
- 自动增量探测本次配置实际选择的表；页面手动刷新只探测工作区依赖表；数据库浏览器单表刷新只探测显式表；System Hook 不触发全局键扫描。
- 自动 `INCREMENTAL_SYNC` 只在 `RECONCILE` 页事务提交后为同源 `TABLE_REFRESH` 暂停并释放 writer；SCAN、权威范围和 System Hook 不扩大让行边界。手动刷新结束后原运行从同一任务 cursor 恢复。

### 变化目标与发布一致性

- ODS 插入、业务列真实变化、tombstone 恢复和真实删除才登记事实目标。lookback 相同行、镜像元数据变化和相同权威集合是派生 no-op。
- `sync_run_fact_targets` 是唯一发布 outbox；`fact_change_heads` 只保存稳定根的最新变化版本、已发布版本和行锁。ODS DML、版本递增和目标 upsert 在同一事务内按稳定键顺序完成。
- 同一运行同一根再次变化必须提升版本、重置为 `PENDING` 并清除旧 assignment 和发布元数据。事实发布锁定同一版本头并从当前 ODS 构建，使交错运行不能写回旧状态。
- 一项事实任务对应一个有界根 ID 批次，没有内部 cursor，也不存在目标数阈值回退。根来源为空是删除旧事实的有效结果。
- 事实替换、旧/新投影范围、generation、投影任务、目标发布和事实任务成功必须在一个带租约 fencing 的平台事务内提交。

### 稳定投影与手工完成语义

- 投影身份只允许 `FULL_EPOCH`、`GLOBAL_VIEW`、`PROJECT` 和 `ISSUE_SCOPE_GROUP`；项目和范围组使用稳定 ID，显示名和事实文本不作为缓存身份。
- 定向事实发布推进旧事实与新事实影响范围的并集。全量发布只由明确全量运行触发，定向目标数量不能改变发布模式。
- 请求 `sourceVersion` 规范包含全量 epoch、全部消费范围的事实 generation、范围组 definition generation 和规则版本，并按稳定键排序。
- 手工刷新在完成依赖表删除探测且仍持有同源 writer 时记录 publication fence。完成状态必须等待 fence 内事实版本和所需投影 generation 发布，不能用“本次没有 DML”推断数据最新。

### 失败恢复

- 已提交目标不依赖镜像父运行成功事件。父运行活动、暂停或任意终态时，持久协调器都可创建或唤醒其唯一事实子运行。
- FACT_REFRESH 无暂时可领取任务但父运行仍可能产生目标时进入 `PAUSED`；可重试失败进入带 `run_after` 的 `RETRYING`；达到上限进入显式 `FAILED`。恢复复用原运行和任务身份。
- 投影任务遵循相同的租约、退避、上限和恢复契约。generation 先推进，因此预热失败不会继续命中旧快照，但手工工作区仍显示未完成。

## 保留与删除

- 保留 `FULL_COMPENSATION_SCAN`，仅用于首次清理、灾难恢复和低频反熵。
- 删除无生产入口的 `COMPENSATION_SCAN`、每范围一个权威任务、每页一个对账任务、200 目标回退、运行完成后 ODS 影响反查和全局快照任务版本。
- 不改变对外 REST、页面 DTO、统计业务口径、导出格式、兼容模式读源、LDAP 或权限边界。

## 后果与验证

日常物理删除的最大陈旧时间由普通同步周期决定，事实与投影计算量随实际变化根和稳定范围增长；删除探测本身随所选表 active 主键数增长，但 JVM 内存保持 `O(batchSize)`。

上线前必须验证单列/复合主键、类型隔离、事务回滚、租约丢失、进程恢复、交错运行、旧/新投影范围、手工 fence、无关快照不变，以及 270 万行固定负载下的吞吐、连接、内存和 GitLab 查询影响。性能基准通过前不得通过增加旁路线程掩盖瓶颈。
