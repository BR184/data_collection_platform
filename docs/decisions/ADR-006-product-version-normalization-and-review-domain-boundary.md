# ADR-006：产品版本归一化与评审数据域边界

## Status

Accepted

## Date

2026-08-04

## Context

评审和系统测试数据来自正式表与老平台兼容快照，历史项目名称存在 `CC2026R4`、`2026 R4`、带中文描述的版本名和组合版本名。旧横向对比还保留 `CC2025R1 -> CC2025R1&R2` 特殊映射，导致平台页面、统计和经授权的外部数据集可能得到不同的版本范围。

评审来源类型也不是一个可以由标题自由推断的枚举。当前实际数据中既有五类稳定类型，也有需求规格说明、测试要点、独立评审、项目计划和导入后落入“其他”的记录；代码走查已经有独立的正式数据域。若将未知类型或代码走查强行塞入普通评审，会污染平台评审质量口径。

## Decision

### 产品版本

1. 有效且已登记的 `product_version_id` 优先作为版本身份。
2. 缺少有效 ID 的历史/兼容记录统一使用项目名称主体匹配：做 Unicode 兼容归一化、大小写归一化和空白清理，识别 `YYYYR<n>` 主体；`CC` 前缀、中文描述、括号、连字符和空格不改变主体。
3. 一个项目名称命中多个已登记主体时展开为多个版本成员，分别参与统计；同一版本内只计一次。`CC2025R1&R2` 因此归入 `CC2025R1` 和 `CC2025R2`，不再映射为一个虚构的 `CC2025R1&R2` 版本。
4. 无法命中、无法完整解析或存在歧义的版本标记为未确定；不进入需要确定版本的统计、外部统计数据集或跨版本汇总，但可在记录/非法数据诊断中追溯。
5. 所有页面、统计服务、快照、导出和 provider 共用这套规则及规则版本，不允许页面级别的特殊映射。

### 普通评审与代码走查

普通评审阶段只包含五类：

| 来源类型 | 规范类型 |
|---|---|
| 需求说明书评审 | 需求评审 |
| 设计说明书评审 | 设计评审 |
| 单元测试用例评审 | 单元测试用例评审 |
| 集成测试用例评审 | 集成测试用例评审 |
| 系统测试用例评审 | 系统测试用例评审 |

`code_review_formal_records` 是独立代码走查数据域。代码走查属于编码阶段，不进入普通评审阶段、五类评审问题总数或评审质量目标；外部消费者的代码走查图表只读取独立代码走查域。

无法确认等同关系的类型保持原始 `review_type`，不根据标题、候选下拉项或“其他”桶自动映射。2026-08-04 的可追溯样例为：

| 未确认来源类型 | 数量（调查基线） | 真实样例 |
|---|---:|---|
| `需求规格说明` | 22 | `review_visible_records.id=-22`，`【焊件模块】需求规格说明书评审` |
| `测试要点评审` | 2 | `id=-330`，`【速览模块】流式传输测试要点评审` |
| `独立评审` | 1 | `id=5`，`外网回归测试评审` |
| `项目计划评审` | 1 | `id=-289`，`【二次开发模块】项目计划评审` |
| `其他` | 4 | `id=-335`，`【企业版】企业文件夹测试要点评审`；`id=-376`，`【二次开发】CrownCAD 拓扑模块API接口封装方案` |

`其他` 是导入/兼容解析无法识别时的追踪桶，不能整体归入五类。`产品用户手册` 当前只有候选项、没有真实记录；出现首条数据前不作为统计类型。

## Alternatives Considered

### 保留 `CC2025R1` 特殊映射

拒绝。它只覆盖一个页面和一个历史版本，不能处理空格、中文描述或多版本组合，且会使同一记录在不同页面得到不同归属。

### 用字符串完全相等匹配项目名称

拒绝。真实项目名称包含版本描述、括号和空格，精确匹配会漏掉本应属于同一版本的记录。

### 将所有未知类型归入“其他”或最相近的评审类型

拒绝。`其他` 中已存在测试要点和 API 方案等异质记录，自动归类会污染统计并且无法审计判断依据。

### 将代码走查作为第六类普通评审

拒绝。代码走查的事实表、来源、模块、缺陷密度和阶段归属不同，已有独立 `code_review_formal_records` 领域；混入普通评审会重复计数并改变质量目标含义。

## Consequences

- 版本筛选、横向对比、评审统计、系统测试统计和经授权的外部数据集共享同一版本成员集合，组合版本可解释且可分别统计。
- 未确定版本和未确认评审类型不会污染平台统计或经授权的外部数据集，但仍保留在平台管理/诊断链路中，便于业务确认后补规则。
- 后续实现必须把版本规则和规则版本作为可测试的共享入口，并为未知评审类型保留原值、稳定 ID 和样例追溯；不能在页面 SQL 或消费适配层添加临时判断。
- 版本规则变化会影响事实、统计快照和经授权的外部数据集；发布时必须按架构文档要求重建受影响事实并刷新快照。
