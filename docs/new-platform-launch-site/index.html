记录类

议题查询：把过滤条件做成可分享的链接

综合搜索、模块关键词、测试阶段、严重程度、缺陷状态、里程碑等条件全部进路由。 查询结果支持排序、分页、CSV 导出，每条议题保留 GitLab 直跳。

  • 主筛选 + 高级筛选两层结构，常用条件即取即用，复杂条件可展开
  • 列宽、排序、分页状态记进用户偏好，刷新不重置
  • 查询条件 URL 可粘贴可转发，回放当时的查询场景
http://localhost:18181/question-metrics/multi-board
看板类

议题多元看板：把质量信号铺成一面墙

顶部 KPI 卡 + 严重等级、阶段分布、模块缺陷、修复率、缺陷原因、延期原因六张图表， 把系统测试议题的核心维度同屏展开，从"哪个模块出问题"到"为什么出"一眼看透。

  • 每张图来自统一统计板接口，前端不重复推导口径
  • 项目维度可切换，URL 即筛选状态
  • 每张图都能下钻到议题明细，从趋势直达原文
http://localhost:18181/question-metrics/home
统计类

系统测试缺陷汇总：多级表头一眼对齐口径

按模块铺开缺陷数量、严重等级、修复状态、未关闭率，多级表头让"数量 / 严重 / 比率" 各成一组，点哪格就下钻到哪格的明细。表底自动累计合计行。

  • 多级列分组，把相关指标视觉聚拢，避免列海里找不到
  • 每个数字都是可点击的下钻入口，跳到带条件的议题明细
  • 规则说明随表交付，现场追问当场可解释
Capability Map

新平台不只是换皮，是工作方式升级。

01

实时更新链路

页面可触发最新数据刷新，镜像同步完成自动推进事实层刷新，减少人工等待和重复操作。

02

不压源库

通过镜像表、本地事实层和增量水位读取，把重查询压力从 GitLab 主库迁出。

03

筛选能力更强

记录页和统计看板共享条件构建器，组合条件、分页、排序、导出和下钻联动。

04

规则说明随表交付

每个看板都展示数据来源、过滤流程、指标定义和样例，方便客户现场追问时快速解释。

05

表格展示可设置

列宽、排序、分页、可见列进入用户偏好，刷新不重置，减少“每次重新找数据”。

06

同步模块更完整

全量、增量、单表刷新、补偿、取消、队列、状态诊断统一到一个同步运行模型。
