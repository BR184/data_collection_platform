# 标签组维度与页面兼容矩阵

本文档给人阅读，机器校验以 `docs/plans/2026-06-10-label-group-dimension-matrix.yml` 为唯一权威源。后续新增、删除或重命名标签维度时，先改 YAML，再同步本说明。

## 页面兼容矩阵

| 页面 | 页面 Key | 支持标签维度 | 第一版接入 | 备注 |
|---|---|---|---|---|
| 评审数据管理 | `review-data-home` | 项目、模块、评审负责人、评审专家 | 是 | 第一试点；评审专家为多值字段，按成员集合相交匹配 |
| 系统测试议题查询 | `question-metrics-issue-search` | 项目、模块、测试阶段、严重程度、紧急程度、里程碑、议题处理人 | 是 | 第二试点；处理人使用 `issue_assignee` / `assigneeName` |
| 客户问题列表 | `customer-issues-cc-product-issues` | 模块、客户问题处理人、紧急程度、里程碑、闭环状态 | 是 | 第三试点；客户问题处理人使用 `customer_assignee` / `assigneeName` |
| 统计板高级筛选 | `statistic-board-*` | 取决于看板 `definition.filters` | 后续 | Phase 6 逐看板验证 |

## 人员维度边界

人员类字段必须按页面事实语义拆分，不允许使用泛化 `owner` 跨页面复用：

- `review_owner`：评审负责人，只用于评审数据。
- `review_expert`：评审专家，只用于评审数据，多值匹配。
- `issue_assignee`：议题处理人，用于系统测试议题类页面。
- `customer_assignee`：客户问题处理人，用于客户问题类页面。

同名人员在不同事实源之间不默认等价。若后续要做统一人员 ID，需要先改事实层和矩阵，不能在标签组里临时合并。

## 不允许成为标签维度的字段

| 字段 | 原因 |
|---|---|
| 有效的独立评审问题数合计 | 指标，不是标签值 |
| 独立评审工作量合计 | 指标，不是标签值 |
| 缺陷密度 | 计算结果，不是标签值 |
| 占比 | 计算结果，不是标签值 |
| 质量看板模块 | 页面结构名称，不是事实字段 |
| 指标与例外条件 | 页面说明文本，不是事实字段 |

## 实施约束

1. 标签组只能属于 YAML 中声明的一个维度。
2. 页面只能应用 YAML 中声明为兼容的维度。
3. `closure_status` 候选只展示并保存“需求如此”，展开时同时匹配“需求如此”和“设计如此”。
4. `review_expert` 这类多值字段必须按“字段值集合与标签组成员集合相交不为空”匹配。
5. 候选值接口必须显式支持 `pageKey` 和可选 `sourceInstanceId`，不得从 session 隐式读取页面或源实例。
