# 模块来源按业务域对齐设计

> 文档状态：当前设计 / 实施中

## 目标

按老平台实际数据链路恢复评审、议题、代码走查和集成测试各自独立的“模块”语义，禁止使用一份全局标签全集或万能解析器向所有页面提供模块候选。

## 设计决策

1. 评审模块分成两类候选：列表筛选只读取当前模式下真实可查询的评审记录；新增/编辑只读取老平台项目 9、79 中全角 `模块：` 标签，并允许录入候选外值。
2. 评审模块保存原始业务值，只做空白清理，不删除“模块”后缀。兼容模式与正式模式只在读源处隔离，不复制两套解析逻辑。
3. 议题模块只识别全角 `模块：`、`工具箱：`；测试阶段继续作为独立事实维度，不能进入模块。
4. 代码走查模块使用独立的老平台 MR 规则 `模块[：|-]`、`工具箱[：|-]`，不能复用议题模块解析器。
5. 页面快速筛选、高级筛选、导出和下钻只消费同一业务事实字段；系统默认标签组只限制结果，不向候选目录注入不存在的模块。
6. 事实解析规则变化通过既有事实重建生效，不增加兼容 DTO、临时 SQL 或页面特判。

## 模式隔离

- 兼容模式-MatchMode：评审和代码走查候选可合并对应老平台读源，但保留原始模块值。
- 非兼容模式：只读取正式事实表，不回退到 Match mode 表。
- 新增/编辑评审的模块目录是录入辅助，不决定列表读源，因此不会造成两种模式相互污染。

## 验收

- 评审快速筛选不再出现没有评审记录的镜像模块。
- 评审录入候选与老平台项目 9、79 的全角模块标签一致，并允许手工录入。
- `草图模块` 等原始值不再被静默改写。
- 议题和 MR 的分隔符规则分别与老平台对应实现一致。
- 兼容/非兼容模式分别验证候选集合，不跨源。
