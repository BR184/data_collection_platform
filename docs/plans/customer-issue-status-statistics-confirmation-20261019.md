### 已确认规则4：闭环、已修复和常规修复率

本次**保留已有F/P公式**，只让确认的真实标签进入其输入；不将所有闭环状态都改算已修复。

| 指标/用途 | 既有规则，本次沿用 |
| --- | --- |
| 整体/严重级别的已修复F | bug_status按既有判据含已修复、待合并、未更新之一；已修复/完成亦命中已修复 |
| 整体/严重级别未修复 | 对应D范围数量减对应F数量；不是未闭环数，也不是GitLab未关闭数 |
| P1/P2/P3已修复P | 状态含已修复/完成或未复现，或GitLab已关闭；不以F替代 |
| 申请延期A | 原申请延期状态判据；不是修复率的第三个互斥桶 |
| 整体/严重级别常规修复率 | count(本组D且F)/count(本组D)×100% |
| 优先级常规修复率 | count(本组D且P)/count(本组D)×100% |
| 关闭率 | 按真实GitLab关闭维度计数，不因存在异常/未复现标签而把议题改成closed |
| 客户解决闭环/滞留判断 | 沿现有客户最终状态成员集合及真实关闭状态，消费修复后的状态；数据异常/未复现可闭环，但不因此改为F=true |

### 已确认规则5：校准后修复率

- E=D中状态命中数据异常或未复现的议题并集，V=D去除E。
- 整体/一级/二级/三级：count(本组V且F)/count(本组V)×100%。
- P1/P2/P3：count(本组V且P)/count(本组V)×100%。
- 分子分母同时剔除，同议题两状态都中只剔除一次；即使异常议题同时有已修复状态，校准分子也必须扣除。
- 申请延期不额外剔除；若它还命中异常/未复现，按并集剔除。需求如此/设计如此仍沿公共排除，不新增校准特例。
- 零分母返回不可计算，页面/Excel显示`/`或既有空值表达，不显示0%；有有效分母而分子为0才为0%。

示例1：10条D，6条F已修复；两条分别有异常、未复现，且都在那6条F中。普通整体修复率60%，校准为(6−2)/(10−2)=50%。

**根因链**：DIRECT 的 `GitlabJdbcValueNormalizer`→`GitlabSourceTimestampNormalizer.normalizeJdbcTimestamp` 把 timestamptz 变为 UTC `LocalDateTime`（正确时刻、丢失偏移表示）；`JsonUtils` 使用平台 Jackson 的 `LocalDateTime` 序列化器，把该 UTC 墙上值按 `Asia/Shanghai` 附加 `+08:00`，或按无偏移文本传给 `jsonb_populate_recordset`；镜像目标列仍为 timestamptz 时按错误时刻落库，形成 −8 小时位移。DOCKER 的 `row_to_json` 字符串自带来源偏移，故 DIRECT/DOCKER 实际表示不同，必须分别验证。`source_updated_at` 是 timestamp 元数据列，历史上因“错误时刻→上海会话转 timestamp”偶然保住了 UTC 墙上值；修复后必须显式 `at time zone 'UTC'`，否则会反向偏移 +8。

**实现方案**（写入边界持有 schema 元数据）：
1. `GitlabMirrorTableStorageService.applyBatch` 在 JSON 序列化前按镜像列物理类型转换：timestamptz 列的 `LocalDateTime`/`Timestamp`/`OffsetDateTime`/`Instant`/`Date` 值统一写成带 `Z` 的 ISO 时刻字符串；`String`（DOCKER 来源）保持其既有偏移；timestamp without time zone 列保持墙上值不变。
2. `buildUpsertSql` 的 `source_updated_at` 表达式按来源更新时间列类型生成：timestamptz 时用 `(p."updated_at" at time zone 'UTC')`，timestamp 时保持 `p."updated_at"`，保证水位轴不随目标会话时区变化。
3. `SyncRunTableTaskExecutor.toLocalDateTime` 改用 `GitlabSourceTimestampNormalizer.normalizeSourceValue`（或等价解析），使 DOCKER 的带偏移字符串能进入增量游标/水位；DIRECT 仍为 UTC 墙上值，轴不变。
