# 旧平台延期停写、双平台对比与待审包指令

## 1. 目标与通过标准
- 停写：原版真实JAR对同一输入发出延期标签PUT；候选的单议题、项目批量、小时任务执行体三路PUT均为0，采集、保存、代码走查及其它GitLab调用正常。
- 接替：两套平台同时处理各自的相同数据，基本规则结果一致、新响应规则正确；随后旧平台停写仍采集，新平台持续自动加标、摘标并收敛，无标签反复。
- 交付：旧原版与停写候选两个包、SHA-256、构建命令及版本、替换及回退说明，交经理审批后由用户部署。

## 2. 红线
1. 不访问生产库/API/凭据，旧入口的@EnableScheduling及资源中的生产连接必须在测试环境全部覆盖或封闭。
2. 测试URL、账号、禁用其它任务的配置不得进入交付包，PAT不得出现在报告里。
3. 不改旧平台延期计算、采集、保存、代码走查、通用setIssueLabels及旧前端源码。
4. 不自动部署。

## 3. 验证清单
在专属任务目录执行，旧源码用D:/projects/spidergitdata-dev副本；新平台固定使用dcp-delay-acceptance-20261027-7e7582af.tar.gz。

- 取下表8个议题，旧走真实入口，新由V3自动取得结果。R=响应已延期，S=解决已延期。

| 样本 | 两边执行的变化 | 新平台预期 |
