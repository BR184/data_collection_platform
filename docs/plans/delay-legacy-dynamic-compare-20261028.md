## 3. 对比方法

相同输入指项目/issue_id/iid、创建时间、全部评论及时间顺序、全部标签、状态一致，并固定测试观察时刻或避开阈值临界点。每阶段先保存基线，再从同一状态开始，不能先让旧平台改完标签，再把已改变的状态当成新平台的输入。

采用以下三阶段，另加短暂干扰诊断：

| 阶段 | 运行方式 | 目的 |
| --- | --- | --- |
| A | 旧平台原版单独写回，新平台写回关闭 | 记录旧版本真实判定、加摘标签与入口边界 |
| B | 恢复相同基线，新平台单独写回，旧写回关闭 | 验证旧基础能力、领导新增规则及保护其它标签 |
| C | 旧平台停写候选仍正常采集，新平台自动同步+写回持续运行 | 验证最终生产接替形态，旧采集不再干扰标签 |
| 诊断D | 仅在本地短暂让两个写回者轮流处理同一条差异样本 | 记录是否互相覆盖；不作为生产共写通过标准 |

新平台应覆盖旧功能，并不意味着标签处处相同。响应模板缺合法计划时间时，旧平台与新规则本就不同；回复模板免响应延期也属于明确新增需求。以领导原始需求判断新平台，不能为了与旧输出相同而恢复旧规则。

已知存量差异须列出真实结果：新旧解决计划评论取值方向、数字天数解析、状态识别以及单议题关闭清标边界；它们既不能隐瞒，也不能自动当作本轮修复授权。用户已确认关闭议题退出延期统计即可，本轮不增加新平台关闭清标签入口。

| 场景 | 新平台必须达到的结果 |
| --- | --- |
| 超期且无模板，P1/P2/P3对照 | 按当前期限判响应延期；不漏原基本能力 |
| 响应模板无计划字段、空白、待定或非法日期 | 达到响应期限后加响应已延期；明确记录与旧结果差异 |

| 只有回复模板；与空响应模板同时存在 | 摘响应已延期；解决延期独立判定 |
| 已过解决截止、未过截止、豁免状态加/摘 | 解决标签按现行规则加摘；不把回复免响应等同免解决 |
| 同议题加R摘S、摘R加S、两项同时有/无 | 两标签正确，无关标签集合保持 |
| 新增/编辑/删除模板评论 | 源变化经自动链进入ODS、事实、标签并回流；删除感知入口单列 |
| 议题关闭再重开 | 关闭同步及统计更新后退出延期统计；旧标签允许保留，重开再判定 |
| 非325、2026年以前、源已删除议题 | 按候选范围不发送；保留边界证据 |
| 老旧期望与当前存量规则有差异 | 单独列清输入、两个实际值和依据，不擅改规则或虚报一致 |

普通自动增量不保证发现物理删除评论。沿用前次已验证的测试删除对账入口，显式记录生效配置与恢复，不因此更改生产默认值。
