## 5. 方案与步骤

### 5.1 总体链路

`登记本轮 → 本轮前置镜像 SUCCESS → 来源 ISSUE 完整发布收敛 → 延期重算生成候选 → 该候选完整发布 → 按当前发布版本分批入队 → worker 重新核验当前版本后调用 GitLab`

每一步由持久身份和状态证明，不用“某条事件到达”或“调用返回”替代。继续使用现有镜像、事实、投影、发布及标签作业队列；不增加另一条同步/事实计算路径。

### 5.2 A 阶段：只读当前有效修订（F1）

- 队列登记与 worker 重读都要求来源 ISSUE 域存在当前 PUBLISHED 身份，在短事务内固定 `publication_id + epoch_id + sequence_no`，复用 `FactReadVisibility.published`。不使用只按 ID 倒序、DISTINCT、取最后一行或未接管行兜底。
- 与现有公开读取采用同样的域/发布锁顺序，在物化候选时持有发布共享锁，防止 GC 抢先回收；不建立前端页面视图，不给后台任务制造页面租约。
- 保留项目 325、2026 起、open、非 GitLab 接口错误等范围；来源缺少完整基线时跳过写回并留下明确原因，不能把“无可用版本”当作无差异。
- 单议题查询必须恰好零或一条当前记录；多条有效记录是数据不变量错误，停止该来源写回并报告，不取首条掩盖。
- 分批登记以业务 `issue_id` 作为 keyset，不用物理修订 `id`；同一固定发布版本内分页。来源标签来自已完成前置刷新并与当前事实收敛的 ODS；不得把未收敛新标签与旧延期判定拼接。

### 5.3 B 阶段：持久化完整发布后的写回交接（F2/F4）

新增一张仅服务本功能的 `customer_issue_delay_closure_requests` 表，**每来源至多一条进度记录**，替换现有 `ConcurrentHashMap/InFlightCycle/schedulingPeriod`。这张表保存跨进程等待，不替代 `read_publications` 的发布权威，也不复制事实内容。

| 阶段 | 推进条件与动作 |
| --- | --- |
| `REQUESTED` | 合并同来源周期请求；读取最新配置。开关开时提交前置镜像，将真实 `mirror_run_id` 与阶段同事务保存；配置关时只走延期事实重算，不产生标签写回授权。 |
| `WAIT_MIRROR` | 只检查本行绑定的运行及其实际来源表覆盖，必须完整 SUCCESS；失败/部分成功记错并按既有退避节奏重新请求，不能靠无关运行事件推进。 |
| `WAIT_SOURCE_PUBLICATION` | 来源 ISSUE 完整依赖就绪、无待发布 heads/全量意图、无占用中的 ISSUE 候选，才可重算；复用同步控制面，不查历史审计全表，不用总记录数阈值。 |
| `RECALCULATE` | 走原 `FactBuildService` 三列重算。在 `publishWithinCandidate` 的构建回调内利用已有 `FactRevisionTarget.publicationId`，将本请求绑定到该候选，并与候选准备在同一事务提交。事务失败不留下虚假等待；不扩大 `FactBuildResponse` 公共格式。 |
| `WAIT_DELAY_PUBLICATION` | 对绑定候选等待真实 PUBLISHED；PROJECTING/READY 均不能入队。候选失败/中止后清理引用并重新基于当前完整输入构建，绝不转为写旧值。重启恢复原候选，不重复开启。 |
| `ENQUEUE` | 固定最新当前发布版本，确认它已覆盖本轮成功发布（同域序号不低于本轮），再按稳定根 ID 分页。候选已被更高完整版本替代时读取更高当前版本，不读取旧版本；若来源继续变化、产生新候选或分页期间指针改变，清除授权/游标，回到收敛与重算，不能拼接两个版本。 |
| `IDLE` | 已处理本轮。完成水位与最后一批入队同事务结算；若期间登记了更高请求修订，只结算本轮，不吞掉后续请求。当前写回版本授权仅在版本仍为当前、来源仍就绪时有效。 |

运行终态事件保留为“唤醒推进”的加速手段，实际条件从库验证；周期短 tick 有界恢复一条来源请求，复用应用异步执行器，不在调度线程轮询或等待投影。新增同功能的推进方法即可，不建设通用工作流框架。每阶段返回后释放线程/锁，等待小时级投影不占用 worker。

持久表最低字段：`source_instance` 主键、归属 `config_id`、`requested_revision/completed_revision/processing_revision`、`phase`、`writeback_requested`、`mirror_run_id`、`pending_publication_id`、本轮已公开序号、`authorized_publication_id`、入队版本与 `after_issue_id` 游标、租约 owner/token/until、`next_attempt_at/last_error/updated_at`。身份均使用来源/运行/候选的真实稳定 ID。当前 `sourceInstanceOf` 固定 default，沿用现有单来源事实，不藉此声称已实现多实例隔离。

- 同来源重复触发合并，不无限积压；租约领取与阶段完成使用 owner/token/processing_revision CAS。旧持有者过期后不得登记候选、入队或结算新周期。
- 写回开启而前置刷新被配置关闭或缺少必需表时，明确拒绝该轮标签写入并保留原因，不沿用 `NotRequired` 直接放行；这属于补齐既有“先刷新再写”的安全条件。写回关闭时仍允许只重算事实。
- 注册镜像与绑定请求、重算与绑定候选、批量入队与推进游标分别原子提交。短事务领取后才进入发布域操作；发布/GC 相关事务按既有域→发布记录→本请求→作业的顺序取锁，禁止先持请求锁再等待发布域。
- 当来源已有活动候选时让位并保留请求，不靠下一小时重新触发恢复；重算零变化也经过既有候选发布结果，随后必须比对实际标签，不能按 affectedRows=0 跳过标签纠正。
- 待处理 `pending_publication_id` 必须纳入 `ReadPublicationRepository` 的回收保护；GC 锁后重查也采用同一保护。完成、取消或中止后清除该引用，不能无限保留历史事实。最后处理 ID/作业来源版本仅为审计字段，不是永久历史读取引用。
- 写回开关关闭时禁止新增标签作业，已有作业按现有语义 SKIPPED；延期事实仍重算。关闭后重新开启必须发起新的前置刷新周期，不沿用关闭前的标签写回授权。
- 错误、阶段、关联运行/候选和等待原因可从既有日志及持久记录定位；不新增用户页面或开关。

### 5.4 C 阶段：worker 执行前再次核验

- 每次执行重新查当前配置、来源完整性/收敛、当前发布身份及本来源本轮授权；来源仍有镜像/事实在途或当前版本不再被授权时保留任务、推迟执行并请求新一轮收敛，不能写旧值，也不能把等待标为 SUCCEEDED。
- 从当前版本重读当前 open 记录并重新计算 add/remove，不能相信作业里保存的旧布尔值。当前关闭、删除或退出范围时 SKIPPED；只允许两个延期标签，其他标签不变。
- 作业增加 `based_on_publication_id` 作为诊断来源，不把它当作强制读取历史版本的依据；既有作业字段为空也走同一个“重读当前版本”入口，不保留旧查询分支。任务成功/失败/跳过均按当前租约 owner/token 条件更新，避免过期 worker 覆盖接管者结果。
- DB 事务内物化并校验计划，HTTP 发送前做最后一次当前身份/开关复核；不持发布域/事实锁等待网络。最后复核与 GitLab PUT 之间仍可能有外部并发变化：不承诺跨系统原子；由后续镜像/周期按最新事实纠正，保留既有幂等 add/remove、429/5xx/网络退避及确定性错误 DEAD 行为。
- 不做队列重试策略的全面重构；如实现发现因周期 upsert 导致退避被重置，必须先补反例、在本作业状态契约内修复，不叠加第二套队列。

### 5.7 验收矩阵

| 场景 | 必须证明的行为 |
| --- | --- |
| 同根旧 epoch/历史/当前/未发布候选并存 | 只读当前一条；当前关闭/删除时历史 open 不复活；两个“有效当前”视为错误。 |
| 本轮镜像未结束，同配置 MR/其它运行先结束 | 不重算、不入队；只有本轮覆盖所需表的 SUCCESS + ISSUE 收敛可推进。 |
| heads=0 但全量意图/候选/依赖未完整 | 不取得写回资格；旧页面可读不构成外部可写资格。 |
| 重算返回、投影未完成或投影失败/中止 | 无该候选标签作业/PUT；失败记录可恢复，旧完整事实不被覆盖。 |
| 候选真实投影与统一发布成功 | 当前发布事实生成恰当双向差异；无变化重算仍修正人为标签偏差。 |
| 镜像绑定、候选准备、候选发布、分批入队各边界重启 | 恢复同一身份或安全重算；不漏请求，不重复副作用，不靠内存事件。 |
| 重复触发、并发推进、租约过期 | 单来源一条工作状态、单议题一条作业；旧 owner 不能覆盖新结果。 |
| 入队分页中换版/任务等待中换版 | 旧游标失效，使用当前完整版本重新登记；不混版本、不按旧任务布尔写。 |
