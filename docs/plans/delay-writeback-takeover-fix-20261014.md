## 2. 目标与边界

老平台在统一延期写回出口停写后，新平台独占维护“响应已延期”和“解决已延期”。保留老平台其他采集和代码走查功能，保持现有页面、指标、权限、延期规则和唯一写回开关。

## 5. 方案与步骤

### 5.1 先固定实现基线和测试范围

员工记录目标 commit/制品/schema、工作树差异、实际运行入口，以及涉及的配置、任务、迁移和共用方法。采用隔离工作单元构建，不覆盖他人工作树、backend/target 或用户正在使用的 18181 制品。包名分支只作发布标记，不在其中继续开发。

### 5.2 用一条来源进度记录替换内存等待

新增 `customer_issue_delay_closure_requests`，每个现行 source_instance 至多一行，保存 config_id、本轮镜像运行号、阶段、请求/处理/完成修订、入队游标、已授权事实版本、租约及最近错误。只保存进度和标识，不保存事实或每轮历史副本。

| 阶段 | 推进条件和动作 |
| --- | --- |
| REQUESTED | 合并请求，读取当前配置。写回开启时提交前置刷新，并将真实 mirror_run_id 与阶段原子保存；写回关闭时保留原延期事实重算能力，不取得标签写入授权。 |
| WAIT_MIRROR | 绑定运行必须是所需表覆盖完整的 SUCCESS。QUEUED、RUNNING、PARTIAL_SUCCESS、取消或失败都不能放行；失败保存原因，按现有退避节奏重试。其它终态事件只唤醒检查。 |
| WAIT_FACT | 复核来源完整性、未发布根、全量意图和相关在途任务。满足条件才调用现有延期重算。重算及受影响版本失效提交后，才转入 ENQUEUE；提交失败不能留下已授权状态。 |
| ENQUEUE | 在一致读取中取得当前事实及真实标签，按 issue_id 做有界 keyset 分页。每批入队与游标推进同事务。相关输入、配置或事实版本改变时撤销授权，重新收敛和重算。 |
| IDLE | 最后一批与完成修订同事务结算。期间到达的更高请求修订继续保留，不被本轮完成清除。 |

运行事件用于加速，短周期检查用于重启恢复。每次有界推进，不阻塞调度线程等待镜像、事实或网络，不每次 tick 再提交一轮刷新。重复触发合并，不取消正在正常运行的前置刷新。

进度领取、推进和释放均校验 owner、领取令牌及处理修订。提交镜像与绑定进度、重算与阶段提交、入队与游标分别保持原子性。先列出实际锁序并复用已有事实写入顺序，避免持有进度锁等待其它任务；HTTP 不在数据库锁内执行。

### 5.3 worker 按当前数据和有效授权执行

每次任务执行必须同时满足：配置仍允许写回、本轮前置刷新成功、来源仍完整收敛、授权与当前相关事实版本匹配、任务租约仍有效。

从当前事实和对应 ODS 标签重算差异，只消费三个延期事实列，不重写规则。关闭、删除、退出范围的议题按现有语义跳过；范围仍为当前已发布规则定义的项目、日期和合法性条件。查询异常不能解释为没有标签；已确认的空标签集合按空集合处理，不用旧事实标签补齐。

任务等待期间来源变化时，保留待评估工作并让编排重新收敛；不把等待算成 HTTP 失败或成功，不因每条任务等待而重复提交前置镜像。HTTP 发送前最后复核配置、授权和租约。

`PENDING/RETRY_WAITING` 及过期 RUNNING 存量任务先取得新一轮授权，再进入同一个执行入口。DEAD 保留失败原因，由运维显式处理，不能换令牌后静默批量复活。

配置关闭时撤销授权、阻止后续发送；重新开启须经过新的前置周期。配置保存与授权失效须有可靠交接，不能只依赖内存事件或 worker 恰好观察到关闭瞬间。

### 5.4 保护领取归属和后续请求

作业保留原唯一业务键，最少追加领取令牌、任务修订及本轮来源绑定。claim 原子生成本次令牌。成功、跳过、死亡、重试和续租都使用 id、owner、令牌及领取修订限定，更新零行表示所有权已丢失。

新差异到达 RUNNING 作业时，保留更高待处理修订，不覆盖本次执行输入；旧修订完成不能清除新修订。源配置缺失或歧义时不发送 HTTP。

GitLab 调用仍只使用 add_labels/remove_labels 增删两个延期标签。网络请求已经发出后无法与数据库撤销组成原子事务；超时后重读最新标签再决定重试，记录发送结果未知的情况。不得声称绝对只发送一次。

### 5.5 迁移与文件范围

预期涉及编排/调度、前置刷新、队列/worker/job、进度持久化协作者、配置变更交接、追加迁移及相应测试。FactBuildService 只在事务交接必要时调整延期入口，保留三列窄写与范围失效。

迁移编号以实施基线的最新版本为准，不能使用原草案的 V20261014_01。旧迁移零修改/删除，锁文件只追加新 SHA。状态表、队列索引须支持按来源/到期时间领取及按 issue_id 分页；不扫描按轮历史日志或复制大表。

## 6. 验收与审批材料

先加入原实现会失败的确定性测试，再修复。以下场景属于本单元验收范围：

| 场景 | 验收结果 |
| --- | --- |
| 本轮镜像仍运行，无关运行先结束，heads 暂为 0 | 不重算、不入队、不 PUT。绑定镜像失败或部分成功同样不能放行。 |
| 无发布正证据、依赖/标签事件历史不完整、全量意图未结算 | 明确等待或拒绝，不能把未知来源当成空差异。 |
| 正常镜像到 ISSUE 收敛，重算有变化/零变化 | 三列与 generation 原子提交；零变化仍纠正外部标签差异；其他列和成员不变。 |
| 绑定镜像、重算提交、分页入队等边界重启或异常 | 恢复同一工作或安全重算，不漏请求，不靠内存事件继续。 |
| 两推进者、过期租约接管、旧 worker 延迟返回、RUNNING 时新请求到达 | 单来源有唯一有效处理者；旧令牌不能结算；新请求不被覆盖。使用真实 PostgreSQL 事务及可控并发验证。 |
| 入队后修改评论/标签、关闭/删除议题、关闭再开启开关 | 执行前重新判定资格，旧授权失效；重新开启经过新周期。 |
| HTTP 成功、4xx、429、5xx、网络超时及成功但响应丢失 | 状态和退避符合既有语义，重读后收敛；非延期标签和范围外议题不变。 |
