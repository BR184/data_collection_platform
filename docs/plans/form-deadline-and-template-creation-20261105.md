## T3 常见场景与预期

| 场景 | 用户可见结果及数据约束 | 验证 |
| --- | --- | --- |
| 填写中发布新版，尚未保存 | 保留旧草稿；提交前发现版本变化停止提交，用户显式转入新版后按新版必填/条件重新校验 | 会话回归与桌面 |
| 保存与发布切换交错 | 保存先提交则记录归旧版；切换先提交则旧版新建返回冲突，输入保留；零跨版/重复记录 | 受控PG交错 |
| 已填完后关闭页面，再打开时已发布新版 | 原草稿、原规格与输入仍可恢复；新版字段变化明确呈现，不自动丢弃或把新字段补0 | 草稿/会话回归 |
| 新版增加必填、删除字段或改选项 | 转入新版仅按稳定身份保留可用输入；移除和不兼容输入可查看/复制，新必填需补填 | 业务样例 |
| 编辑旧版已保存记录时发布新版 | 继续按记录所属版编辑，保存/取消原位恢复，记录不搬表 | PG与桌面 |
| 两人新增、两标签编辑同一记录 | 新增独立；旧修订CAS冲突保留本地输入并提供当前记录，不覆盖他人 | 已有回归缺口补齐 |
| 保存成功但响应丢失，期间发布新版 | 保留首次提交快照，按原幂等证据核验，返回原记录或明确未完成 | 会话与服务回归 |
| 管理员同时修改草稿或退役 | 管理草稿CAS保护；退役后新建/编辑拒绝，未提交输入保留，历史可读 | PG与会话 |
| 账号切换或权限撤销 | 不暴露前账号草稿，不代写他人记录；后端每次验证实际权限 | 既有鉴权回归加自查样例 |
| 跨来源同号、复制模板、发布空新版 | 来源/模板/版本不串数据；导出归属明确；既有Issue统计/标签和走查统计不被新模板污染 | PG业务样例 |
