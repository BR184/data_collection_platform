# CCProduct表单就绪后投放执行方案

## 当前状态与待办

状态：供用户审批。选用现有自动同步，CC来源间隔设为10分钟；响应/回复就绪后由平台使用`ci_robot`发链接。审批后员工在原表单功能分支实施。

| 编号 | 目标 | 完成标准 |
| --- | --- | --- |
| L1 | 纠正业务范围和可写判断 | CCProduct（325）的真实资源按状态返回可写能力，未采集/待登记资源可写为false |
| L2 | 接入就绪投放任务 | 初始事实成功公开、两模板就绪后登记任务；失败发布零投放，重复同步保持同一任务 |
| L3 | 完成评论发送与恢复 | 本地GitLab收到一条含响应/回复入口的评论；重启、重复触发和超时恢复保持去重 |
| L4 | 联验并交付 | 普通账号经评论链接保存，自动进入事实和延期页面，改期/作废继续传播 |

本次申请批准代码、前向迁移、必要前端状态适配及专属本地GitLab联验。生产配置、正式凭据启用、真实授权、黄金update、main和正式包分别审批。

## 范围与用户流程

范围为CCProduct（项目325）新Issue的响应/回复，使用完整来源身份和已配置项目绑定；项目号仅作为本次业务范围配置，不写成通用服务常量。生产MR仍评论，代码走查非法页保持旧源，历史COMMENT身份沿用。

流程：新Issue → 自动同步 → 初始事实成功公开且两模板FORM身份就绪 → 持久投放任务 → `ci_robot`一条评论 → 普通账号填写 → 既有事实、筛选和延期标签链。

10分钟使用CC来源现有间隔配置，影响同一来源其他项目的同步频率；评论投放仅覆盖获准的325范围。沿用`GitlabCompensationScheduler`和`SyncRunSubmissionService`的到期判断、互斥及复用机制。本方案不新增Webhook或另一套采集入口。

等待时间为到下次计划的间隔，加调度检查、排队、采集及事实发布耗时。就绪后直接唤醒投放worker，不再额外等一轮10分钟。首次启用按既有FORM切换点盘点未投放资源，生产清单随启用申请确认。

## 改造内容

| 单元 | 选定做法 | 代码入口 |
| --- | --- | --- |
| 业务样本 | T2/T4统一使用325的真实Issue及本项目里程碑；用例与绑定同步调整 | 黄金表单夹具、端点用例及本地初始化 |
| 就绪判定 | 新增共享判定服务，供详情、任务登记及发送前复核；写事务继续执行原有锁内检查 | `FormRecordContextService`、`FormRecordAuthorityService`、`FormRecordService.detail` |
| 初始投放登记 | ISSUE成功发布事务中按本次发布根登记投放任务，与发布原子提交；提交后只做worker唤醒 | `FactTargetPublicationService`及新增投放服务 |
| 补漏与发送 | worker按有界批次分页补扫当前已发布的获准FORM资源，唯一键登记遗漏任务；短事务领取、事务外HTTP、条件结算 | 新增投放任务仓库、worker及GitLab评论客户端 |
| 页面状态 | 区分准备中、可填写、只读；准备中关闭新建/保存，保留已有草稿与未知结果核验保护 | 详情DTO/前端类型、`CollectFormView.vue`必要状态文案 |

已存在的`FormFactPublicationEvent`只覆盖消费了新表单输入的公开。初始空表单也必须能发入口，因此投放登记接在ISSUE成功发布入口，不依赖该事件或已有填写记录。

### 就绪合同

| 情况 | 详情表现 | 投放结果 |
| --- | --- | --- |
| 平台尚无完整资源身份，例如未采集的999999 | 200、准备中、可写为false | 等待采集 |
| 已有资源，持久FORM身份待登记 | 200、准备中、可写为false | 等待登记 |
| 已登记COMMENT | 只读，保持评论路径 | 无表单链接任务 |
| 两模板FORM身份、绑定、范围及已发布版本有效，且该资源初始事实已公开 | 有权限账号可填写 | 允许投放 |
| 范围退役或停写 | 对应只读状态 | 等待或停止该任务 |

详情按所请求模板判定就绪；合并评论要求两个模板分别通过判定。检查完整来源/项目/Issue身份、模板归属及范围/版本；接收者权限由当前登录账号独立裁决。首次投放只要求未填写时的初始事实就绪，保存后的重算继续走既有链路。

详情增加结构化就绪状态和业务原因；GET保持只读，未知资源保持准备中，写入口继续拒绝未就绪资源。管理页及已批准布局保持，只适配上述功能状态。

### 任务与评论合同

- 新增一张持久投放任务表，唯一身份为完整来源＋项目＋Issue＋投放用途，记录就绪发布证据、状态、领取令牌/租约、下次尝试及GitLab评论ID。版本更新和重复同步复用同一投放身份。
- 任务登记与事实公开同事务；worker领取和结算使用短事务与令牌CAS，HTTP在事务外执行。周期补扫及租约恢复承接重启后遗漏工作。
- 一条评论包含“填写响应”“填写回复”两个链接，使用现有稳定路由及平台对外地址，不固定表单结构版本。
- 评论附本功能专属稳定标记。发送结果未知时按标记及机器人作者核对GitLab评论，命中后补记成功，查询覆盖分页；仍无法确认时保留待核对状态并报告。去重只处理本功能标记，不修改其他工具的评论。
- 发送前重新检查来源启用、两模板就绪及目标归属。明确未发送的临时错误采用有界退避；认证/权限配置错误暂停并报告；已删除或移出范围的资源终止投放。
- 投放按来源显式启用、默认关闭。`ci_robot`凭据由部署环境独立注入，发送前核对实际账号；与既有延期标签令牌分开，任务和日志只保存凭据引用。生产启用另行授权。

## 实施顺序与验收

员工沿用原功能主分支和专属环境，先完成L1，再实现L2/L3，最后L4。前向迁移保持既有迁移不变；接口新增字段及任务副作用同步登记黄金目录。

| 验证对象 | 最低充分验收 |
| --- | --- |
| 间隔 | 可控时钟验证10分钟到期、未到期及活动运行复用；无需实等十分钟 |
| 资源与身份 | 未采集、待登记、FORM、COMMENT四类样例，详情能力与写入口一致；拒绝写入时记录/审计/head不变 |
| 发布与队列 | 真实PG覆盖发布回滚零任务、重复登记唯一任务、并发领取和租约恢复；初始无填写记录也能登记 |
| 评论恢复 | 替身覆盖成功、明确失败、已成功但响应丢失；恢复后本功能评论仍为一条，其他工具评论保持 |
| 本地真实链路 | 325新Issue经自动同步就绪后，真实`ci_robot`评论；普通账号打开两入口，保存后进入延期页面，再改期/作废验证变化；一条历史COMMENT作对照 |
| 视觉与文案 | 桌面核对准备中、就绪两态，原UI布局保持 |

代表性本地链路一次即可；最终代码完成受影响常规回归，黄金严格比较沿已批准执行范围交差异，快照生成/update仍单独审批。

## 交付与停止条件

交付按职责提交的实现、迁移与测试，提供一个真实链路结果、投放任务/评论对应关系及实际接口差异。同步更新当前进度和升级步骤，评审通过后再申请生产启用。

本地GitLab、平台对外地址或`ci_robot`授权缺失时停在对应联验步骤并列明缺项，已完成单元可阶段送审。出现来源不符、COMMENT被改判、重复投放或既有写回回归时停止送审并修复。

审批事项：同意上述范围后，员工开始L1—L4；本次先在专属本地环境使用10分钟配置，生产CC来源间隔和自动评论启用随部署申请执行。
