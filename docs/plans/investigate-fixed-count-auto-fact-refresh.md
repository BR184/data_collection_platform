# 系统测试已修复数量自动事实刷新调查计划

## 进度与中间物

- 状态：调查中。
- 已完成：确认用户现场现象、仓库规则、当前进度、事实层架构契约、工作树状态和既有活动计划。
- 当前进行：追踪 GitLab 状态标签从源端、镜像层、影响对象、自动事实子运行、`issue_fact` 到系统测试缺陷汇总快照的完整链路。
- 验证状态：现场已知“单表刷新无效、手工全量事实重建后恢复”；尚未以源码、运行记录和版本历史确定断点，不修改业务代码。

## 恢复线索

- 当前阶段：代码与版本证据采集。
- 恢复后首条命令：`rg -n "FACT_REFRESH|rebuildAllFactsForConfig|affected.*Issue|label_links|resource_label_events" backend/src/main backend/src/test`。
- 基线：当前 `main` 工作树包含大量用户未提交改动；必须分别审查 `HEAD`、工作树和内网部署版本，不覆盖或回退既有修改。

## 目标与边界

- 用户需求：确定 CC2026R4 回归测试各类型“已修复”数量曾全部为 0、单表刷新无效、手工全量事实重建后恢复的真实原因，并给出可长期维护的修复方案。
- 成功标准：用新平台输入到输出调用链、老平台统计口径、Git 历史、代表测试或只读数据证据证明根因；明确受影响版本/入口、修复位置、历史数据修复要求、回归测试和现场验收方法。
- 禁止：未取得证据前不修改业务代码；不把当前工作树候选改动误称为已部署能力；不改动老平台只读源码；不以页面显示或手工重建成功代替自动发布断点分析。

## 约束与背景

- 新平台数据链为 GitLab 源端 -> ODS 镜像 -> 事实层 -> 统计快照/实时查询 -> 页面；镜像成功和事实发布成功必须独立判断。
- 架构要求每个整体成功或部分成功镜像运行提交独立 `FACT_REFRESH` 子运行，且页面刷新必须等待该子运行完成后才能标记最新。
- 老平台基准源码位于 `D:/projects/spidergitdata-dev`，只提炼行为和口径，不复制实现。
- 现场内网数据和部署 commit 暂未直接接入；可从代码确定的缺陷与仍需现场记录证明的版本事实必须分开陈述。

## 证据与根因

- 已知现象：GitLab 议题已有“状态：已修复/完成”；新平台系统测试缺陷汇总的“已修复”曾为 0；单表刷新不能恢复；手工全量事实重建后恢复。
- 待证明：状态标签的权威源表和事实字段；同步任务是否完整更新关系集合；关系变化是否携带父议题影响；镜像父运行是否可靠创建事实子运行；增量事实构建是否消费正确影响集；统计快照是否按事实源版本失效。

## 方案与步骤

1. 定位前后端页面入口、“已修复”统计条件、下钻和快照键。
2. 深读事实构建的标签解析、`bug_status`/关闭状态规则及增量影响对象算法。
3. 深读全量、增量、单表刷新和 System Hook 的任务规划、ODS 写入、父运行汇总、事实子运行提交和执行路径。
4. 对照老平台状态标签解析与“已修复”统计口径，排除页面或口径差异。
5. 查询 Git 历史和当前工作树差异，确定最近“同步后自动事实重建”能力的实际覆盖范围与遗漏入口。
6. 用现有测试或最小只读复现实验验证断点；必要时列出目标环境所需的最小 SQL/运行编号证据。
7. 输出根因链、受影响范围、权威修复设计、历史数据修复步骤和防回归验证矩阵。

## 决策记录

- 已选：从一条已修复议题反向追踪源关系、ODS、事实和快照，同时正向追踪同步运行状态机；原因是必须区分源数据遗漏、影响集遗漏、事实运行遗漏和缓存陈旧。
- 已选：将 `HEAD`、当前工作树和内网部署包视为三个可能不同的代码状态；原因是工作树已有事实与权威关系同步改动，不能据此推断现场版本。
- 否决：把“手工重建可恢复”直接归因于缓存；原因是手工重建也会重写事实并提升事实源版本，现象本身不能区分事实陈旧与快照陈旧。

## 接口契约

- 调查阶段不新增或修改 API、表结构、函数签名和交互协议。
- 待核对契约：镜像运行与 `FACT_REFRESH.parent_run_id` 的一对一完成链、精确关系任务的 `lookupScope`、事实影响对象载荷和事实源版本/快照失效规则。

## 风险与假设

- 风险：没有现场 `sync_runs`、`sync_run_table_tasks`、事实版本和部署 commit 时，可能能证明代码缺陷但不能唯一还原现场运行编号的失败点。
- 风险：当前工作树包含尚未提交的权威关系同步改造，可能已经部分修复本次问题；必须通过 `git diff` 与历史提交区分。
- 假设：截图中的“已修复”统计由 `状态：已修复/完成` 标签派生，而不是 GitLab issue 的 open/closed 状态；将由新老平台源码确认。
