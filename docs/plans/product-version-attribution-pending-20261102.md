| 数据/入口 | 当前实现 | 影响 |
| --- | --- | --- |
| 质量看板代码走查 | `QualityBoardCodeReviewReadSupport.resolveProductVersionScope` 将组合项目展开为版本成员，普通版本取 dev；SP 按既有精确分支规则 | 组合记录可以同时进入 R1、R2，不能自动区分后续两版的数据 |

| BI 版本与评审/编码读源 | 名称解析的实际结果和边界统一记在 [BI 数据契约](../bi-dashboard/data-contracts.md#pending-version-attribution-20261102) | 与质量看板评审范围不一致；组合版本不能仅靠新增下拉选项拆开 |
| 新平台议题阶段 | `IssueLabelRules` 先按中文全角冒号前缀分类；无该冒号时识别系统测试/回归测试/集成测试关键词，再匹配阶段目录 | 项目标签不是测试阶段；仅将项目标签填入“测试阶段名称”不会扩大标签识别范围 |
| 缺阶段议题 | 按版本/轮次筛选的系统测试统计依赖 testing_phase | 缺阶段记录不进入该轮次范围；不代表所有按项目或里程碑查询的页面都不可见 |
| 老平台组合特例 | `StaticDataController` 对横向导出的 CC2025R1，把评审查询名称改为 CC2025R1&R2；议题/走查仍取原名称；R2 入口另查 CC2025R2 | 这是整份借用组合评审的局部特例，没有按记录拆分两版，也不是两版自动共享 |
