1. 区分“已请求取消”与“取消完成”。最终CANCELLED必须意味着旧代际已失去提交资格，全部普通任务/关系范围已完成、终止或持久移交；不能仅按普通RUNNING表任务为0确认。
2. 在领取、续租、批次提交、末页推进、终态提交中统一校验父运行身份/状态、owner或等价fencing代际。不能只在读取前检查一次；**最终写事务也必须校验**，覆盖查源返回后才发生取消/接管的竞争。
3. 统一控制事务的锁顺序，并记录线性化点：来源协调/父运行与子任务、范围、版本头按固定顺序取锁；源库IO在平台写事务外。取消与提交谁先获得合法提交权，结果必须确定；不要通过长期持锁等待源查询来“解决”并发。
4. 取消后的旧心跳不能续活旧代际，旧回调不能重新激活父运行或覆盖新owner。已提交合法数据和水位保留；未完成任务/关系范围/待发布根要有持久、幂等的后续接管路径，不只靠重扫lookback碰运气。
5. 处理已存在的“父终态、范围仍活动”等历史控制记录，按来源/所选子表与实际owner状态有界回收、登记接管，不清表，不把活动租约错误转交，不把未完整关系解释为空。恢复标记与新范围登记同事务，重复取消、重复恢复、崩溃后再恢复不得丢工作或双owner。
6. CANCELLING期间的新刷新不得把取消中的运行当作一个可成功复用的普通刷新；请求可合并或等待有效新运行，响应必须给真实runId及等待原因。
7. 验证镜像→事实→投影→统计最终闭包，仍使用来源READY/版本头/发布栅栏权威判据，不恢复parent_run_id猜测。连续自动触发/尾部补跑不能使可发布事实永久饥饿。此次修复不恢复D-26。

#### S3：统一进度、中文呈现与接口契约

- 使用一个权威进度模型贯穿API、最近日志、展开详情、抽屉和工作区。至少分别提供：唯一源表数；分页任务总数及排队/运行/重试/成功/失败/取消数；关系范围对应状态；当前阶段/等待原因/最后业务进展时刻；镜像与事实/投影状态。
- 扫描与应用量按明确的成功提交批次口径统计，表分页和关系范围分项列示，失败回滚不当成功累计，重试不重复累计同一次提交。它们是处理行次，不冒充去重实体数或数据库执行计划的物理扫描行数；汇总采用一致快照/代际并显示更新时间。
- 心跳不等于业务进展；长时间无业务进展应显示正在查源、等待锁/重试、取消或等待关系/事实等真实证据。没有证据时明确“阶段待确认”，不硬编进度百分比或自动改为成功。
- 正常提交/状态/进度用集中定义和结构化事件呈现中文，覆盖Scheduled incremental sync、复用/尾部补跑、基线等待、取消、关系接管和事实等待；保留原始错误、SQLSTATE、run/task/lease身份供明细和复制。历史正常消息也应可读，不能全靠一条英文精确匹配。
- 不改业务查询、计算或导出内容。同步元数据API若新增/删除字段或改变含义，先形成字段对照、类型、单位、历史空值语义及调用者清单；同包前后端直接收口到目标模型，不加v2/双轨掩盖。若发现真实外部消费者，列明兼容对象/期限/退出条件交经理裁定，不自行建立永久兼容层。
- 所有产出端点继续按D-08登记/保护，新增接口与权限登记同批完成。同步进度/中文元数据变化是预期差异候选，但**不等于已批准更新黄金快照**。

**S1 基数与全量→增量交接**

- 时间来源在 `SyncRunTablePlanningService.createFullScanTask` 读取开始前取一次来源时钟：来源列类型含 `with time zone` 时执行 `(current_timestamp at time zone 'UTC')`，否则执行 `current_timestamp::timestamp`；结果写入根扫描任务 `baseline_watermark_at`。不读宿主时间、全量结束时间、ODS 最大值或 `MAX(updated_at)`。空/不可解析结果直接失败，不当成安全基线。
- `MONOTONIC_PRIMARY_KEY` 全量在读取前取来源当前最大主键游标（无行时写 `[]`）；非空游标类型必须与现有 JSON 游标契约一致。
- 基线只在 `SyncRunCompletionCommitService.finishOwnedRun` 的同一终态事务中、运行 SUCCESS 且类型为 `FULL_SYNC` / `FULL_COMPENSATION_SCAN` 时，由 `SyncRunBaselineActivationService.activate` 激活：按 `state_id` 取本运行最早根扫描任务基线；时间水位只前进不后退；单标量主键游标只在更大时前进；`[]` 不覆盖已有游标；不可解析游标记录告警并跳过。
- 首次全量未完成时：派发器不再领取同来源的 `INCREMENTAL_SYNC/TABLE_REFRESH/SYSTEM_HOOK`；增量还要求至少一个启用表状态和全部启用时间表/单调主键表都有可用基线。`SyncRunWorkerService` 预检在活动全量存在时把增量置 `RETRYING`（5 秒后复查，原因“等待首次全量同步建立增量基线”），无可用基线时失败并提示先完成成功全量。`SyncRunYieldService` 使用同一 `SyncRunReadinessService` 判据；无基线时全量不让位给无法运行的增量。`resolveTaskWatermark` 对缺失时间水位不再回退 1970，直接拒绝。
- 普通后续增量沿用既有固定上界、时间+真实 PK 游标、lookback、末页原子推进和覆盖判据；本次不改各来源/表策略目录。

**S2 取消、租约与恢复**

- 统一锁顺序：父运行 `sync_runs` 行 → 表任务行 → 权威范围行；来源库 IO 在所有平台写事务之外。所有受保护写入先执行 `SyncRunReconciliationCoordinator.lockStageMutation(runId, runLeaseOwner)`，条件是 `run_type <> 'FACT_REFRESH'`、`status='RUNNING'`、`cancel_requested=false`、`lease_owner` 匹配且 `lease_until >= current_timestamp`；失败抛 `SyncRunLeaseLostException`。范围提交、表页提交、删除对账页和阶段规划都走同一入口。
- 取消线性化点：`SyncRunCancellationService.requestCancel` 在单事务内先 CAS `status='CANCELLING'`（携带原状态），随后终止所有 `QUEUED/RUNNING/RETRYING` 表任务和全部活动权威范围，最后写 `CANCELLED` 并清空运行租约。先取得运行行的旧提交合法保留；取消先取得运行行后，旧页提交/范围提交/领取/续租全部失败。返回值恒为 `CANCELLED`，不再把“确认取消”留成 `CANCELLING`。
- 旧代际不得续活：表任务领取和续租、范围批次领取和续租、事实任务领取/续租/提交、投影任务领取/续租/提交都校验父运行状态、owner（或事实运行租约令牌）、取消标记和租约有效期。`SyncRunLeaseService.recoverTimedOutRuns` 将过期 `CANCELLING` 收敛为 `CANCELLED`，其余过期活动运行收敛为 `TIMEOUT`，并在同一事务终止子任务/范围、复位 `sys_table_registry` 的 SYNCING。
- 范围接管：`SyncRunAuthoritativeScopeRepository.adoptOrphanedScopes(runId, sourceInstance, selectedTables)` 在单事务内以 `FOR UPDATE SKIP LOCKED` 选取“父运行已终态，或 RUNNING 且租约缺失/过期”的旧范围；旧行改 `CANCELLED` 且写 `recovered_by_run_id/recovered_at`，同事务插入新运行 QUEUED 副本，`on conflict do nothing`；有效租约不被抢走。新运行启动、增量派发前执行接管，重复执行不产生双 owner。
- 成功终态不允许仍有活动子项：`SyncRunCompletionCommitService` 在终态事务内统计活动表任务，SUCCESS 时若 >0 抛错；其余终态把表任务和范围统一置终态；成功全量随后激活基线。事实刷新取消额外把该运行的 `fact_build_tasks` 活动任务置 `FAILED + manual_disposition='CANCELLED'`、释放根批次，把 `fact_projection_refresh_tasks` 活动任务置 `FAILED + CANCELLED` 并刷新发布栅栏；未发布根仍由版本头保留，后续事实运行可再次接管。

**S3 进度模型与中文呈现**

- 唯一模型 `SyncRunProgressService`（只读、`REPEATABLE_READ` 快照）产出 `SyncProgress`，同时供 `SyncRunStatusService` 的当前进度和 `SyncRunLogService` 每条日志的 `progress` 使用。字段口径：
  - `sourceTableCount`：本运行 `SCAN` 任务中不同 `source_table` 数（排除带 `lookup_scope_json` 的精确任务）；尚未规划时为 `null`，不伪造。
  - `pageTasks`：`task_stage='SCAN'` 的总数及 QUEUED/RUNNING/RETRYING/SUCCESS/FAILED+CANCELLED/TIMEOUT 分项；`scannedRows/appliedRows` 与状态计数同一条 SQL 取，来自任务已提交页累计值，失败回滚不累计、重试不重复累计；它们是处理行次，不是去重实体数或数据库物理扫描行数。
  - `reconciliation`：`task_stage='RECONCILE'` 的总数/成功/失败/运行计数与扫描、应用行次，单独列示，不混入页任务。
  - `scopes`：权威范围总数及 QUEUED/RUNNING/RETRY_WAITING/SUCCESS/FAILED/CANCELLED 分项；不把范围行数当来源表数。
  - `facts` / `projections`：`FACT_REFRESH` 运行的事实构建与投影任务总数、成功、运行、等待重试、失败、人工待处理、取消计数；事实 `affected_rows` 只累计 SUCCESS。
  - `stage`/`stageText`、`waitingReason`/`waitingReasonText`：由上述计数和运行状态集中判定，没有证据时为 `UNKNOWN`/“阶段待确认”；不硬编百分比。
  - `lastBusinessProgressAt`：取任务 `cursor_updated_at/finished_at/started_at`、范围 `finished_at/started_at`、事实与投影任务 `finished_at/started_at` 的最新值；心跳字段不参与。
  - `progressUpdatedAt`：模型查询时刻；`mirrorStatus/factStatus/projectionStatus` 分别表达镜像工作、事实发布栅栏（TABLE_REFRESH）以及事实/投影任务状态。
  - 兼容既有 `totalTables/completedTables/runningTables/failedTables/scannedRows/appliedRows`：镜像运行分别映射为页任务总数、成功数、运行数、失败+超时数、扫描/应用行次；事实运行映射为事实构建任务计数。`completedTables` 不再包含失败/取消终态。
- 中文文案集中由 `SyncRunMessageCatalog` 生成：`stageText`、`waitingReasonText`、当前消息（运行号+阶段+等待原因/终态）。状态词沿用界面既有权威词表（处理中/重试中/已完成/已取消/已超时等）。前端 `translateSyncMessage` 只负责历史英文正常消息（含 `Scheduled incremental sync`、复用/尾部补跑、取消、范围接管、事实等待），未知文本原样返回；原始错误、SQLSTATE、run/task/lease 身份继续以 `errorSummary/rawError/dispositionReason/error_message` 展示，不写入中文替代。
- 最近日志、事件预览、抽屉和监控面板统一调用同一翻译入口；事件的原始 `message` 作为 tooltip/明细原文保留。同步元数据 API 不新增端点，仅扩展 `SyncProgress` 与每条日志的 `progress` 对象；调用者为本仓库 `MirrorRunMonitorPanel.vue`、`MirrorSyncLogTable.vue`、`MirrorRunLogDetailDrawer.vue`，无外部消费者。

**状态迁移图（镜像运行）**

`SUBMITTED → QUEUED → RUNNING → SUCCESS|PARTIAL_SUCCESS|FAILED|TIMEOUT`；`RUNNING/RETRYING/PAUSED → CANCELLING → CANCELLED`（同事务完成，不再等待）；`RUNNING → RETRYING → RUNNING`（表/范围/基线等待）；`RUNNING/RETRYING → PAUSED → QUEUED`（让行后由调度恢复）。`FACT_REFRESH` 共用外层状态，子任务状态为 `QUEUED/RUNNING/RETRY_WAITING/SUCCESS/FAILED`，人工处置标记 `NONE/REQUIRES_DECISION/CANCELLED`。
