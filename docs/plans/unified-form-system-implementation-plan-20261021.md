## 全局红线

1. FORM/COMMENT按持久权威判定，不随填写情况翻转。
2. FORM沿既有事实、授权轮次、队列和发送前复核链流转；禁止用直接插入验收业务记录、改事实、删head或新增绕过开关替代真实消费，不增加旁路写回器。
3. 旧记录原位保留，不搬迁、不补0、不按同名强并字段；字段身份、语义及冻结类型/单位/域共同决定可比性。
4. 本人归属、幂等、CAS、目录、审计与head同事务完成。
5. 生产MR继续评论，代码走查非法页整页旧源；本地受控FORM联验使用已批准UI。
6. 黄金执行、快照生成/update、main、正式包、升级和授权各按已批准范围执行；未经批准不扩范围，失败不以重试、延时、忽略或扩大掩码掩盖。

## 三张结构性约束表

代码变更按所涉路径核对以下合同。

### 锁序

| 路径 | 取锁顺序 | 集中入口 |
| --- | --- | --- |
| 新建 | 序列→范围SHARE→实例/记录/目录→审计/head，含实例外键隐式锁 | `FormRecordWriteService.create` |
| 编辑/作废 | 范围SHARE→所属记录CAS→审计/head | `updateStorage/voidStorage` |
| 草稿/退役/删范围 | 范围UPDATE→草稿CAS或范围变更；预览追加冻结证据 | `FormTemplateAdminService` |
| 发布创建 | 范围UPDATE→草稿/预览核验→任务登记 | `FormPublicationTxService.createPublication` |
| 发布执行/DDL/切换/接管 | 序列→范围UPDATE→任务UPDATE→head基表ID升序，锁内复核租约/token | `FormPublicationTxService`、`FormHeadSwitchService` |
| 旧数据登记 | 序列→范围UPDATE→目录/版本/事件，序列高水位单调前进 | `FormV6RegistrationService` |
| 捕获/结算 | 范围SHARE→head基表UPDATE→capture，持锁至公开提交 | `FormHeadCaptureService` |
| 目录事件 | 事件ID升序领取→范围UPDATE→游标→表单/事实head | `FormDirectoryEventCursorService` |
| 权威登记 | 权威唯一键→head补建，核验既有身份 | `FormIssueAuthorityRegistrar` |
| 导出 | 读取冻结版→追加审计 | `FormRecordExportService` |

### 事务边界

| 边界 | 要求 |
| --- | --- |
| 记录写入 | 记录、目录、审计、head及事实唤醒登记原子提交 |
| 发布 | BUILDING建空结构；enter/apply为短事务；apply原子提交指针、角色、集合、事件、head及撤栅栏 |
| 旧数据登记 | 锁后核验、目录/角色及完成证据同事务 |
| 结构核验 | 临时建表、ALTER、反解析及DROP固定同一物理连接 |
| 事实公开 | 候选构建使用REPEATABLE_READ；最终公开事务复核完整输入并结算consumed |
| 目录事件 | 事件、游标、表单head及事实head同事务 |
| 延期请求 | AFTER_COMMIT中requestRound使用REQUIRES_NEW，提交后再唤醒worker |
| 延期重算/授权 | 三个重算入口使用REPEATABLE_READ，重算与进度/授权同事务；onConfigSaved保持原事务 |

### 输入签名

| 消费点 | 绑定与复核 |

| 旧数据登记 | 全部副本及冻结规格的类型化全值证据，保留NULL/空串和数组边界；锁后逐条核目录与完成证据 |
| 发布/恢复 | 范围状态、原指针、草稿修订、规格、绑定修订/哈希及owner/fence/lease |

## T4 本地GitLab真实链路验收

**环境：** 复用已有GitLab小样本初始化方法，使用任务专属实例、平台库和服务。Issue响应/回复使用CCProduct（325）及其真实里程碑/标签；普通账号与仓库沿已有样本准备。GitLab Web/API与镜像读源属于同一实例。

**就绪判定修正：** 详情的可写状态与现有写入口采用一致的资源、持久FORM权威及范围/版本判断。平台尚无资源身份或权威待登记时返回准备中、可写为false；已有COMMENT身份按原方式处理。以未采集编号、真实资源待登记、FORM就绪及COMMENT四类业务样例验证读写一致。

**主线：** 创建一条命中延期筛选范围的真实Issue→手动打开对应填写链接→普通账号填写响应/回复→自动形成事实并进入页面筛选→改期后延期判定和本地标签随之改变→作废后按剩余有效输入重算页面、统计和标签。日期由执行者依据既定SLA选择。

**MR预期：** 两条走查分别用时10、20分钟，合计30、均值15；正式统计和导出与有效记录一致。

**版本预期：** 正常发布仅调整显示名的版本后，原链接可访问旧记录，记录位置和统计结果保持。

**完成标准：** 一个代表性样本能从真实资源、普通账号操作追到入库、已发布事实和页面结果；改期、作废自动收敛，历史COMMENT对照保持。
