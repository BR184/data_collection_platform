## 全局红线

1. FORM/COMMENT按持久权威判定，不因今天有没有填写而翻转；各模板分别取其权威输入。
2. FORM进入既有事实、授权轮次、队列及发送前复核链，不增加旁路写回器。
3. 旧记录原位保留；缺失/NULL不补0；可比性按稳定身份、语义、冻结类型/单位/域判定，同名不等于同义。
4. 本人归属、幂等、记录CAS、目录、审计与head在同一写事务完成。
5. 生产MR继续评论；代码走查非法页整页使用老平台；批准的管理页与填写页布局保持。
6. 黄金、main合入、正式包、升级与真实授权分别取得批准；生产切换按外部前置单独批准。

### 事务边界

| 边界 | 提交要求 | 原因 |
| --- | --- | --- |
| 记录写入 | `FormRecordWriteService`同事务提交记录、目录、审计、head及事实唤醒登记 | 失败整体回滚 |
| 模板发布 | BUILDING建空结构；enter/apply为短事务；apply原子提交指针、角色、源集合、事件、head和撤栅栏 | 构建不停写，切换不可部分成功 |
| 旧数据登记 | `FormV6RegistrationService`锁后核验与目录/角色/完成证据同事务 | 原数据变化即拒绝，重入不重复登记 |
| 结构核验 | `FormVersionStructureVerifier`的临时建表、ALTER、反解析、DROP固定一个物理连接 | CHECK分组、FK动作、索引/序列漂移核验不依赖连接池恰好返还同一会话 |
| 事实公开 | `FactTargetPublicationService.publishWithinCandidate`为REPEATABLE_READ；最终公开事务复核候选完整清单并结算consumed | 输入推进后旧候选不能公开 |
| 目录事件 | `consumePending`的事件、游标、表单head、事实head同事务 | 重启可续跑，失败不丢唤醒 |
| 延期请求 | AFTER_COMMIT调用`CustomerIssueDelayClosureProgressRepository.requestRound`，仅该方法REQUIRES_NEW，返回后再submitAdvance | worker领取前请求已对另一连接可见；事实回滚不登记 |
| 延期重算/授权 | `startMirrorRound/refreshFactsOnly/authorizeEnqueue`为REPEATABLE_READ，重算与进度/授权同事务；保留onConfigSaved原事务 | 输入与授权原子提交，不拆独立小事务 |

## 验证分级规则

| 风险 | 典型对象 | 最低验证 | 不要求 |
| --- | --- | --- | --- |
| 数据或授权受损 | 迁移、权限、并发写入、锁序、租约、事务边界 | 受影响路径真实PG回归；有并发风险才控制两会话交错，断言守恒、唯一归属或零副作用 | 逐项突变、逐方法交错、容器清理回读、逐文件哈希、小改动反复全量 |
| 业务结果错误 | 公式、选择器、来源权威、签名/类型编码 | 固定业务样例及反例断言；数组编码先单元验证，跨JDBC边界才加真库样例 | 纯算法启动真库、浏览器矩阵、重复升级演练、强制突变 |
| 展示与文案 | 布局、提示、文字、按钮层级 | 桌面核对受影响状态；代码改动通过类型/构建检查 | 纯展示新增业务测试、后端全量、移动端矩阵 |

每次只跑受影响范围；缺陷先复现，再验证修后结果。正式候选跑一次必要默认套件和批准的黄金，后续按新增变化补验。失败先查原因，不延时、重试或忽略掩盖。资源正常释放，Git提交/推送遵循仓库规则，材料只保存支撑结论的必要证据。

### T2 成功样本与导出提案

**目标：** 最小FORM成功夹具和快照提案先给审核方审，再交用户批准具体内容。

**做法：** 保留所选issue_response样本、19个校验/空态用例、代表性命令端点及有值Excel，采用以下单一路径：

1. 固定Web地址在来源种子阶段设置，列出configs/binding-options等有意变化；保持来源启用。基线通过真实新增API保存后，让原FACT_REFRESH、事实与投影生产者真实收敛，再捕获基线。要求记录可读、head已消费、事实绑定同一FORM签名。禁止删form_change_heads/fact_change_heads或关闭来源来制造静止。
2. 基线收敛后，复用黄金现有暂停周期生产者机制控制调度：暂停`SyncRunDispatcherService`、`FactRefreshTaskWorkerService`及相关表单消费者，保持写入口和AFTER_COMMIT真实入队。命令用例锁定记录/目录/审计/head及真实FACT_REFRESH队列变化；按既有REPLAY前后恢复全部实际副作用。读用例读取已消费基线，不让未消费命令状态混入读快照。不新增`suppress-fact-refresh`开关或旁路写回器。
3. 补`SyncRunSubmissionService.submitRun`实际影响的运行/控制表和序列恢复清单；Excel导出审计虽可复用既有测试，也须前后恢复到基线，不能任其累积改变数据库浏览器结果。固定请求User-Agent，精确列出仍需批准的表列掩码，不能掩业务值/签名。最少代表样本即可，不追加三模板页面矩阵。
4. 事实应显示该样本的真实计划与FORM签名；统计增量按页面范围计算。若仍为0，说明哪条范围规则排除了样本，不能以消费者被禁用作依据。通知成功响应严格使用现有四字段`sourceAddress/projectId/requestIid/resourceType`；测试期导出临时授权按原有行精确恢复，正式授权保持独立。

**完成标准：** 新夹具、新快照具体到行和单元格，真实基线消费与命令入队状态均有预期；按完整副作用重算数量，59份不能直接沿用。保留19响应/16表缺失清单。生成前补具体夹具SQL或等价构造步骤及其准确行数，先交审核方，再交用户确认夹具/掩码/生成范围。执行先严格compare收集已覆盖差异，批准update后生成、审阅并严格复比；新用例响应缺失会阻断该用例后续表断言，用静态清单补齐，不能据此改成先无授权update。

### T3 升级开关与恢复步骤

**目标：** 在升级runbook交可执行步骤表，给审核方审，用户确认目标环境及窗口。

**做法：** 保留真实140/156/158前缀、一次性迁移、冷启动、重建及配套备份/旧包回退结构，修正以下执行问题：

| 问题 | 选定改法 |
| --- | --- |
| Flyway checksum直接比仓库SHA-256 | Flyway自身校验数据库历史CRC；仓库脚本另验资源SHA-256，两种算法不直接比数值 |
| 停服务后要求PENDING/QUEUED全部清空 | 先冻结新入口，在旧服务仍运行时让在途任务收敛，再停全部旧执行者；待办队列按持久协议保留并暂停领取，不删除、不无限等待无人处理的队列 |
| 全局调度值与恢复参数依赖默认值 | 重建阶段显式列总开关true及各外部入口关闭值；记录进程参数/Compose与数据库原值，恢复每一项均取原值，不统一设true。冷启动同时核实自动配置/初始化入口，沿已有隔离入口阻止外部Mongo连接 |
| 必需域只统计已存在行的NULL指针 | 从实际来源及页面依赖闭包列应有域，左连接检查缺行、指针缺失及非PUBLISHED；配置中的兼容/正式数据域也纳入，CAT未配置才排除 |
| 写回恢复隐含启用或停写条件冲突 | 原值恢复与新写回切换分开；只在旧所有者已停写且取得独立授权时恢复发送。不能一边要求任务运行，一边禁止所有新发送 |
| 原值记录使用select * | 只列恢复必需字段；backup_settings不输出remote_password_cipher等凭据列 |

新表迁移后再查；每步注明原值、临时值、恢复值及对应真实配置/表列。最终正常Compose启动也必须保持同一恢复结果。

**完成标准：** 每步有命令、前后状态和停止条件；身份/迁移不符、未知外部目标、必需域不完整或校验失败即停止恢复作业。重建期间没有外部采集/写回提前开启。
