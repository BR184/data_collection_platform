## 全局红线

1. FORM/COMMENT按持久权威判定，不因今天有没有填写而翻转；各模板分别取其权威输入。
2. FORM进入既有事实、授权轮次、队列及发送前复核链，不增加旁路写回器。
3. 旧记录原位保留；缺失/NULL不补0；可比性按稳定身份、语义、冻结类型/单位/域判定，同名不等于同义。
4. 本人归属、幂等、记录CAS、目录、审计与head在同一写事务完成。
5. 生产MR继续评论；代码走查非法页整页使用老平台；批准的管理页与填写页布局保持。
6. 黄金、main合入、正式包、升级与真实授权分别取得批准；生产切换按外部前置单独批准。

变更前列影响路径，按三表检查整条调用链。复用集中入口；检查相邻入口及隐式外键锁，不为每个方法另造协议。

### 事务边界

| 边界 | 提交要求 | 原因 |
| --- | --- | --- |
| 记录写入 | `FormRecordWriteService`同事务提交记录、目录、审计、head及事实唤醒登记 | 失败整体回滚 |
| 模板发布 | BUILDING建空结构；enter/apply为短事务；apply原子提交指针、角色、源集合、事件、head和撤栅栏 | 构建不停写，切换不可部分成功 |
| 旧数据登记 | `FormV6RegistrationService`锁后核验与目录/角色/完成证据同事务 | 原数据变化即拒绝，重入不重复登记 |
| 结构核验 | `FormVersionStructureVerifier`的临时建表、ALTER、反解析、DROP固定一个物理连接 | CHECK分组、FK动作、索引/序列漂移核验不依赖连接池恰好返还同一会话 |
| 事实公开 | `FactTargetPublicationService.publishWithinCandidate`为REPEATABLE_READ；最终公开事务复核候选完整清单并结算consumed | 输入推进后旧候选不能公开 |
| 目录事件 | `consumePending`的事件、游标、表单head、事实head同事务 | 重启可续跑，失败不丢唤醒 |
| 延期请求 | AFTER_COMMIT调用`CustomerIssueDelayClosureProgressRepository.requestRound`，仅该方法REQUIRES_NEW，返回后再submitAdvance | worker领取前请求已对另一连接可见；事实回滚不登记 |
| 延期重算/授权 | `startMirrorRound/refreshFactsOnly/authorizeEnqueue`为REPEATABLE_READ，重算与进度/授权同事务；保留onConfigSaved原事务 | 输入与授权原子提交，不拆独立小事务 |

## 验证分级规则

| 风险 | 典型对象 | 最低验证 | 不要求 |
| --- | --- | --- | --- |
| 数据或授权受损 | 迁移、权限、并发写入、锁序、租约、事务边界 | 受影响路径真实PG回归；有并发风险才控制两会话交错，断言守恒、唯一归属或零副作用 | 逐项突变、逐方法交错、容器清理回读、逐文件哈希、小改动反复全量 |
| 业务结果错误 | 公式、选择器、来源权威、签名/类型编码 | 固定业务样例及反例断言；数组编码先单元验证，跨JDBC边界才加真库样例 | 纯算法启动真库、浏览器矩阵、重复升级演练、强制突变 |
| 展示与文案 | 布局、提示、文字、按钮层级 | 桌面核对受影响状态；代码改动通过类型/构建检查 | 纯展示新增业务测试、后端全量、移动端矩阵 |

每次只跑受影响范围；缺陷先复现，再验证修后结果。正式候选跑一次必要默认套件和批准的黄金，后续按新增变化补验。失败先查原因，不延时、重试或忽略掩盖。资源正常释放，Git提交/推送遵循仓库规则，材料只保存支撑结论的必要证据。

## 当前待办的执行细节

### T1 文件级快照判定

**目标：** 交新增、删除、更新表，每行列文件、字段、原因、既有掩码/规范化入口、处理结论和预期，给审核方裁定。

**做法：** JSON比较忽略对象键序，保留数组顺序、值类型与字段缺失；只用目录声明的路径掩码，读取帧校验真实来源后规范化。原30份中22份可归读取帧/既有掩码/键序，其余按下表落实；原81份也按同一规则复核。

| 差异 | 处理方向 |
| --- | --- |
| 旧写入口6份、替换用例2份、读取上下文1份 | 前8份随入口/用例删除，最后1份恢复，按实际目录登记 |
| main已批准的延期、时间、质量结果 | 保留业务值并叠加读协议，不能整文件覆盖 |
| CAT两页无完整点 | 预期HTTP409/READ_VIEW_UNAVAILABLE |
| issue_fact发布列与历史行 | 物理历史与当前可见记录分开，旧业务值不变，当前样本仅可见1条 |
| 表清单、候选消息、同步6/6→16/16 | 核对publishedReadRequired、实际16表规划和完成判据，保留计数比较 |
| 人员候选 | 专家479项、负责人459项成员一致；按活跃日期/name及历史合并次序定位顺序变化 |
| sourceVersion | 引用对真实绑定来源的校验，不能递归删掉版本/时间字段 |

**完成标准：** 每行可判定保留、生成、删除或修实现；有未归因业务变化就停止。144份存量差异不作为整批update范围。

### T2 成功样本与导出提案

**目标：** 最小FORM成功夹具和快照提案先给审核方审，再交用户批准具体内容。

**做法：** 保留19个校验/空态用例，补代表性的详情、新建/编辑/作废及有值的按版Excel，导出纳入EXPORT并复用Excel单元格规范化。列准确资源、范围、版本、权威、字段值、账号/测试权限、表和行数，列完整副作用及恢复方式。旧COMMENT值保持；新增样本影响统计时列预期增量。三模板选择器、作废排除、空版表头复用已有正式测试；兼容性完整性SQL的元数据写入与业务行分开说明。

**完成标准：** 新夹具、新快照具体到行和单元格，可一次审批；清单包含19响应、16表缺失项。首次compare可能先在响应断言失败，不能保证收齐后续表差异。批准生成后再严格compare。

### T3 升级开关与恢复步骤

**目标：** 在升级runbook交可执行步骤表，给审核方审，用户确认目标环境及窗口。

**做法：** 按真实140/156/158迁移集合和校验和分支检查，新表迁移后再查。顺序为备份/停写→migrate单次乱序升级→后台全关的service校验→仅开放本地接管/事实与投影重建→核对发布点→逐项恢复作业。列总开关、镜像/dispatcher、延期预同步/写回、match-mode、CAT、DGM候选、备份的状态及恢复值。CAT未配置不列必备完整域；首次无完整点按读取契约处理。回退使用配套数据库备份与旧包。

**完成标准：** 每步有命令、前后状态和停止条件；身份/迁移不符、未知外部目标、必需域不完整或校验失败即停止恢复作业。重建期间没有外部采集/写回提前开启。

独立新模板模型、版本绑定解耦、退役恢复需用户确认；本批只执行T1—T3。

**机器人链接提案：** 选固定短路径，如`https://平台域名/f/1/mr/7/3`或`/f/1/issue/7/9`，复用来源配置ID、项目ID和资源IID，不新增短码映射表。服务端按来源ID解析并校验完整身份，不猜默认来源；一个资源一个固定地址，不绑定版本。评论显示“填写代码走查表”或“填写问题表单”，Issue内选响应/回复。机器人创建资源时即可组织路径；尚未镜像则页面显示待同步，提交沿原校验。地址不授予权限，旧链接继续可用。现有notification-payload只返回资源四字段，来源ID取得及认证需对接CI_ROBOT。用户确认后另列最小实施范围。
