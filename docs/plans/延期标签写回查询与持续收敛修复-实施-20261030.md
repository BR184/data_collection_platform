## 原始需求与完成标准

消除三项缺陷：30 秒延期查询超时；自动同步推进事实版本后剩余写回任务等待下一小时；失败后重复重查；慢 GitLab 请求占用公共调度线程。完成标准：同一数据判定与标签结果不变；重复事件、两个推进者、重启与失败退避下请求幂等、任务不丢、已一致者不重复 PUT；默认套件、相关真实链路与发布前黄金严格 compare 通过；不更新黄金快照。

## 约束

- 不新增持久字段、表、迁移或类；执行器 Bean 属于现有配置类。
- 判定公式、模板/日期规则、关闭议题边界、页面与统计口径不变；旧平台继续停写。
- 保留严格版本授权、真实时钟租约、单实例单条 HTTP 并发。
- 所有验证使用独立库/端口/容器；不操作生产、内网实例或其他 AI 的工作树与资源。

## 关键契约

| 对象 | 约定 |
| --- | --- |
| `gitlab_sync_configs` 恢复条件 | 仅当 `stage=IDLE`、`authorized_fact_version` 非空且小于当前 ISSUE 版本、无有效租约、同来源存在 `PENDING/RETRY_WAIT/RUNNING` 作业时，`request_revision+1` 并回到 `REQUESTED` |
| 退避 | `failure_count>0` 时 `next_check_at=GREATEST(COALESCE(next_check_at, now), now)`；成功越过失败步骤后由既有授权/完成路径清零 |
| 旧任务结算 | 同来源、`authorization_revision` 低于本轮且状态为 `PENDING/RETRY_WAIT` 的作业置 `SKIPPED`；与 `completeRound` 同事务 |
| 发送执行器 | Bean `customerIssueDelayWritebackExecutor`：core=max=1、queue=0、线程前缀 `customer-delay-writeback-` |
| 批次 | 每批最多 6 条；相邻 PUT 起始间隔 ≥ `customer-issue-delay-writeback-worker-delay-ms`（默认 5000） |

## 风险与假设

- 统一谓词依赖 ODS `mirror_deleted` 的 NOT NULL 动态 DDL 契约；若现场存在可空旧表，需另行报告结构差异而非静默兼容。
- 生产已存在的 `idx_ods_gitlab_issues_project_iid` 与目录同名同定义，既有库复用；新库由控制面补建。
- 连续链路需要真实隔离 GitLab 与 6 秒 PUT 代理，占用较多本机资源，执行前后须按资源清单停止并保留证据。
